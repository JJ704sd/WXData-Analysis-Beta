# 输入与故障说明

## 数据和密钥

选择本人有权读取的 Windows 微信4.x `db_storage`，或已经解密并合并WAL的副本。保留账号媒体目录，才能读取对应图片和附件。仅复制数据库不能补出未缓存原件。不同客户端数据库布局未适配时保留错误，不将缺失记录写成完整结果。

数据库密钥文件沿用 `keys` 数组，记录包含 `key_hex`（32字节的十六进制）和 `salt_hex`（16字节的十六进制）。提供多个账号/分片的密钥时，程序按当前数据库salt选择，并核对页HMAC和SQLite完整性；无需填写账号目录名。

图片文件沿用 `keys` 数组中的 `aes_hex`（16字节的十六进制）。旧 `sourceRoot` 仅为优先尝试提示，不作为迁移后拒绝密钥的条件。原件必须匹配消息完整MD5；没有原件校验值的缩略图必须能真正解码为支持的图片，且继续标记为缩略图。最多128个图片候选、密钥文件最多64KiB，不扫描磁盘找钥。

也支持组合JSON：`keys` 存放数据库密钥记录，`imageKeys` 存放图片密钥记录。在数据库密钥框选择这个文件后，图片密钥框可留空；程序在同一文件中选择。此格式兼容原先分开的两个密钥文件。不要把实际密钥复制到聊天或让模型读取文件正文。

## 解析结果

- `业务阅读.txt`：非表情记录的完整阅读上下文。
- `messages.jsonl`：逐条源记录和出处，可能含私有元数据，保留本地。
- `chat.html`：离线阅读页。
- `media-recovery.jsonl`：媒体缺口、缩略图和未验证候选。
- `manifest.json`：条数、类型、解码、引用与媒体状态及完整性信息。
- `解析结果.md`：程序生成的固定汇报，内容与 `reporting.replyMarkdown` 一致；提供三格式文件链接。宿主用 `reporting.presentation` 的完整参数呈现文件，再原样使用汇报，不重写媒体数量或状态。

媒体报告读取 `mediaSummary` / `mediaSummaryText`：图片原图、缩略图、本地预览、缺失、未加载五类互斥；附件和表情单独统计。范围与图片总览一致，包含普通、转发及引用，单位是引用处数，不按文件去重；总数不是不同图片张数。旧 `mediaStatuses` 和 `businessMediaStatuses` 是混合媒体且不含引用展开，不能当作图片统计。图片在程序内查看。PDF、Office文档及视频通过电脑已有默认查看器打开，解析和保存文件不要求安装Office。

`mediaSummary.attachmentTypes` 按扩展名统计每种附件引用，大小写合并，无法识别的归为 `unknown`；每类保留 total/ready/previewOnly/missing/notLoaded，总数与附件统计一致。不要凭文件名列表重新算或把可用数当总数。JSONL、JSON、MD通过 `exportFiles` 和 `reporting.presentation.files` 提供，文件呈现失败须保留程序给出的本地链接。

## 配置迁移

桌面与Skill共用对应客户端的固定用户目录，已有配置优先保留。没有用户配置时自动迁移附近有效旧配置并复制其引用密钥；多账号、远处旧目录或失败时，在手动页“导入旧版配置”选择旧settings.local.json。高级自定义DataDir保持独立。详见[配置迁移说明](../../../docs/local-chat/配置迁移说明.md)。

## 人工等待与导出

群列表和当前群顶部显示未复核/已复核，可筛选所选未复核群；筛选保留勾选。复核窗口“全选复核项”和“清空勾选”仅修改当前群窗口的四项勾选，不保存或导出，仍需人工点击“确认复核完成”。宿主不得代点这些按钮。

没有指定群时可用 `-Mode Desktop` 打开界面，让人工按群ID选择。日期与媒体选项在窗口设置。解析后停在 `awaiting_review`，人工逐群保存复核，再点击“一键导出所选群”才导出；宿主后续读取本次完整 `resultFile`，不启动第二个同群请求。Skill的 `-Mode Export` 明确拒绝，不沿用旧版绕过人工复核的批处理入口。

## 常见故障

默认 `run.ps1 -ChatName "群名"` 会解析并打开；参数路径由宿主从技能目录自动解析，用户无需填写。设置固定保存在当前 Windows 用户 `%LOCALAPPDATA%\LocalWechatArchive`，更新技能仍复用；换电脑首次可自动发现目录并点击“一键自动配置”，已有离线副本和密钥也可手选。`resultFile` 回执的 awaiting_review 表示解析预览完成但待人工复核，ok=false不等于解析失败；completed 且 humanReview.status=confirmed 才表示正式导出完成。started/parsing仍在启动或处理，needs_source/needs_chat等待窗口操作，failed表示未完成。不得以重新调用Parse或直接Export代替人工确认。

- 首次使用/needsSource：打开“自动配置（推荐）”页；发现唯一账号时已填好，多个账号先选一个，然后点“一键自动配置”。没有现成密钥时需要先登录本人微信。已有密钥或离线副本仍可在“手动选择 / 离线副本”页提供路径。
- 缺少匹配数据库密钥：首页salt或HMAC不匹配，不能只复制密文完成解析。只有离线密文不能通用推导AES密钥。
- 图片未取得：检查所选图片密钥、当前账号媒体文件及格式。移动数据目录本身不会再要求修改密钥里的旧路径。
- 列群失败且提示附件索引缺钥：补齐对应索引库密钥；用户只需正文时可以显式使用 `-NoMedia`。
- 自己/对方未知：可另填明确的本人微信ID；不能把群主、目录名或第一位成员当作本人。
- 自定义或重定向的数据目录：手动选实际路径；默认账号发现不保证覆盖所有自定义位置。
- 源文件变化、WAL或HMAC校验失败：等本机写入稳定后重新更新副本，不跳过坏页假报成功。

## 自动配置与可选本机恢复

首次启动会从当前用户的常见目录、Windows文档目录及可读的微信目录配置提示中发现账号；不全盘搜索，不遍历磁盘寻找密钥。自定义位置未被提示覆盖时仍需手选。唯一目录自动填好不等于已验证账号身份，多账号必须由用户选定。

点击“一键自动配置”先尝试明确引用及程序自身工作目录 `keys/` 中最多16个已有文件，每次按当前数据库内容校验。成功时无需读取微信进程；否则才为本次操作调用下述恢复组件。恢复成功后在工作目录保存组合JSON（数据库 `keys`、可用的图片 `imageKeys`），记住路径并继续原请求。图片恢复失败可继续读取已验证正文，但必须保留缺图状态。

未检测到微信进程时提示先手动登录；微信已运行但不持有所选目录时提示账号/副本不对应。不会自动登录、切换账号或反复扫描。

只有用户明确请求本机当前账号取钥时才使用 `-Mode RecoverKeys -Source "本机实际db_storage"`。需要对应Windows微信正在登录并持有所选数据；单独拷贝的旧副本通常没有对应进程，不能以此推导密钥。先通过文件锁归属和进程身份确认唯一微信进程，再限时读取并验证候选，数据库按salt及HMAC校验，图片需至少两个独立样本通过。默认数据库读取上限512MiB、30秒；图片额外最多20秒、256MiB。完整库解密和SQLite验证通过后才报告数据已加载。

结果仅包含新生成私有文件的路径和状态，密钥内容写在本机工作目录的keys子目录，不打印。未知归属、布局不支持、权限拒绝、超时、错钥和源变化均明确失败，不回退扫描其他账号。图片恢复失败不假装已恢复；已有密钥仍可手动选择。包内无需另装Python或取钥依赖。

本机生成的Skill及可执行程序不包含任何账号密钥和聊天数据。此包的Windows执行链可以本地复测；WorkBuddy宿主的具体导入、权限和模型数据策略需按本机版本确认。

保存复核仍返回awaiting_review，可含reviewConfirmed=true，不表示已导出。所选群全部复核后，用户点击一键导出；批次包含batch.json和导出清单.md。宿主不自动点击导出，未完成或失效的群阻止整批，部分失败按清单重试，成功群不重复生成。
