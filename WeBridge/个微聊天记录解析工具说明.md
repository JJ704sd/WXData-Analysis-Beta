# 个微聊天记录解析工具说明

群聊导出区点击“选择位置…”可指定本机目录，程序记住上次选择，每次新建独立批次子目录，记录与已取得的媒体、附件一起保存。已有文件保留原位置，可在“打开文件 → 另存当前群到指定位置…”保存完整副本。外部目录导出的进度需使用v47或更新版本恢复；恢复时保留所选目录及原工作目录缓存。

更新日期：2026-10-27
对应源码版本：桌面程序 v71 / 个微、企微群聊 Skill 1.51.5；支持多选群聊批量解析、人工复核后导出、重启恢复、清单与跨群分析。私聊版本为 1.20.3，使用独立入口。运行包需自行构建，宿主导入与完整人工链路按实际回执单独确认。
本版流程为：确认账号 → 展示全部本地群 ID 与名称 → 勾选一个或多个 ID 批量解析 → 逐群人工复核 → 复核完成后一键导出所选群。保留账号配置和个微、企微独立入口。详见[复核导出流程](docs/local-chat/复核导出流程.md)。企微双击 `Start-WeCom.cmd`，或在WorkBuddy说“打开企微界面让我多选群批量解析”。详见 [企微使用说明](docs/local-chat/企微使用说明.md)。
适用范围：本人有权访问的 Windows 个微4.x数据，以及现有企微5.0.12.6018适配。当前验证采用合成数据；下文既有验收记录保留历史版本标识，不表示本轮已连接真实账号。

## 1. 目前可以用它做什么

这是一个读取本地微信数据副本、解析指定群聊天记录并提供查看和导出的工具。个微与企微Skill已分别打包，名称为“个微-本地聊天解析”（wechat-local-archive）与“企微-本地聊天解析”（wecom-local-archive），默认客户端和配置分别绑定。

- **列群并按 ID 选择**：展示当前账号全部本地群名与 ID，也可搜索筛选；只解析确认的目标群。账号准备可能需要解密共享数据库副本。
- **人工复核后导出**：预览正文及媒体缺口后，人工完成四项检查并确认，再发布 JSONL / JSON / MD；`review.json` 留存复核项、备注和本次结果摘要。
- **使用方便**：可以双击桌面程序，也可以在 WorkBuddy 中说“解析示例混合群”。
- **用户免安装运行环境**：程序已内置所需运行库，不用安装 Python、Docker 或数据库服务。
- **首次自动配置后记住设置**：自动发现本机账号目录，登录本人微信后点“一键自动配置”尝试恢复并校验密钥；已有离线副本与密钥仍可手选，成功后自动复用。
- **保留原消息出处**：能查看发送人、时间、正文、引用和转发上下文，便于核对业务需求、结论和待办。
- **如实显示缺口**：原件、缩略图、未取得媒体分别标记，不把缺失内容推断为已读取。

附件正文能力与边界见 [附件正文解析说明](docs/local-chat/附件正文解析说明.md)。原有结果不覆盖，需重新解析生成正文。

正常解析只读取原数据，在工具自己的工作目录制作副本和导出，不向微信发送消息，也不联网补拉历史记录。

## 2. 功能与覆盖范围

| 功能 | 当前可以实现 | 使用边界 |
| --- | --- | --- |
| 发现账号、列出群聊 | 发现常见本机数据目录，或读取手动选定的账号，并列出群聊 | 自定义目录可能需要手选；目录名称不代表已验证的本人身份 |
| 指定群解析 | 按实际群名或会话 ID 读取全部本地记录，也支持日期范围导出 | “全部”指所选副本中存在的记录；名称重复时需要选定正确群 |
| 发送人、时间和双方身份 | 保留数据库能确定的发送者、时间及原始出处 | 自己/对方依赖可靠的本人 ID；未提供时保持未知，不猜测 |
| 文字、链接和 @ | 解析正文、链接、引用及结构化 @ 信息 | 正文里的“@某人”与数据库中的真实成员 ID 分开保存 |
| 图片查看 | 图片总览集中展示普通消息、嵌套转发和引用中的图片，支持放大、定位原消息；导出含独立图片阅读页 | 按引用保留发送人、时间和来源，原图、缩略图、本地预览、缺失与未加载分别标注；依赖本地缓存和匹配图片密钥 |
| 文件附件及正文 | 校验原件并提取PDF、Word、Excel、PPT与文本正文，写入JSONL、JSON、MD及业务阅读 | 原文件与正文状态独立；旧DOC/PPT为部分支持，可选择本机 OCR 识别扫描文字，超限与失败保留原因 |
| 转发聊天 | 解析嵌套消息，逐层展开，展示原发送人、时间、正文和可用媒体 | 存在层级与数量上限；未取得的媒体继续保留缺口 |
| 引用回复 | 展示内嵌引用；条件满足时关联同群中可确定的原消息 | 来源缺失、编号重复或身份冲突时不强行关联 |
| 视频和语音 | 识别相关消息信息，并在支持的映射及缓存条件下取得原文件 | 私有编码、播放和语音库密钥有额外条件；未包含语音转写或视频内容理解 |
| 表情 | 尽可能识别并保留可取得的内容 | 作为可选内容，解析失败不阻塞业务阅读 |
| 业务阅读和导出 | 保留非表情记录的业务上下文，生成阅读文件和结构化数据 | “业务阅读”是方便阅读的记录集合；业务结论仍需结合原文和缺失媒体判断 |
| JSONL、JSON、MD 导出 | 每次解析/导出同时生成三种文件，无需额外选择或转换 | JSONL/JSON保留相同完整字段和嵌套结构；MD侧重可读内容，媒体链接需配套保留assets目录 |
| 业务事项整理 | 宿主 AI 可依据选定记录整理需求、结论、待办，并引用原消息 | AI 归纳与确定性解析分开看待，不能把发送人自述、计划或推测当成已验收事实 |

未识别的消息类型会保留原始字段或原文并标记状态。当前覆盖不等于所有微信版本和私有格式都能完整解释。

## 3. 在 WorkBuddy 中如何使用

### 首次使用

1. 在 WorkBuddy 的“专家·技能·连接器 → 技能”中导入完整 Skill ZIP 并启用。
2. 新建任务，输入：

   > 解析示例混合群

3. 首次弹出“自动配置（推荐）”页，程序自动发现本机账号目录；唯一目录已填好，多账号先从列表选定一个。先手动登录本人微信，再点“一键自动配置”，不需要寻找密钥 JSON。
4. 程序先校验本机已有密钥，没有时限时尝试恢复所选账号的数据库与图片密钥。加载成功后刚才的解析请求会自动继续，不需要重新发送指令。已有离线副本和密钥可切到“手动选择 / 离线副本”页，选文件后“保存并加载”。
5. 完成后，程序打开指定群的业务阅读窗口，可查看图片、附件和转发内容。

数据库密钥和图片密钥可以分开选择，也支持一个 JSON 同时包含两类密钥；使用组合文件时，图片密钥框可以留空。不要把密钥正文粘贴到对话里。

### “数据目录”和“匹配密钥”具体指什么

这里的数据来自电脑已经保存的微信历史记录，不是登录密码，也不要求从聊天窗口逐条复制。

| 设置项 | 选择什么 | 它解决什么问题 |
| --- | --- | --- |
| 账号数据目录 | 单个账号的 `xwechat_files\账号目录\db_storage`，或它的上一级账号目录 | 读取 `message`、`contact`、`session` 等数据库；保留账号旁的 `msg` 等媒体目录，才能继续定位图片和附件 |
| 数据库密钥文件 | 此前单独准备、包含所选数据库解密密钥的 JSON | 让工具读取加密数据库中的正文、发送者、时间和附件索引；微信不会自动为用户提供这个 JSON |
| 图片密钥文件 | 已有的图片解密密钥 JSON；组合文件已含图片密钥时可留空 | 用于部分加密图片缓存；只有数据库密钥不代表所有图片都能查看 |

例如，一份本地历史数据可能如下：

```text
<WECHAT_SOURCE_ROOT>\账号目录\
  db_storage\
    message\       聊天记录数据库
    contact\       联系人和成员信息
    session\       会话信息
    hardlink\      部分附件索引
  msg\             本机已缓存的图片和附件（实际子目录随版本变化）
<DATABASE_KEYS_JSON>
<IMAGE_KEYS_JSON>
```

数据框选择 `db_storage`，数据库密钥框选择“数据库密钥.json”，图片密钥框选择“图片密钥.json”，再点“保存并加载”。工具先校验密钥、建立独立副本，再搜索目标群；确认后只读取该群的历史消息。

“匹配”指密钥能通过所选数据库的解密和内容校验，不能靠修改文件名、把任意文本另存为 JSON 来得到密钥。账号目录、密钥 JSON 和程序的 `settings.local.json` 是三种不同文件；设置文件只记住路径，不等于密钥。已经解密的副本可不填数据库密钥，但图片仍需对应媒体文件和必要的图片密钥。

本机已经配置成功的用户可直接复用设置，或选择“使用已有工作台配置…”。换电脑只需首次选路径的前提是：已准备好数据以及匹配密钥。没有密钥时，界面的本机恢复入口仍有版本和登录条件，不能保证成功。

### 没有现成密钥时怎样自动配置

这类 JSON 是恢复工具将校验通过的密钥保存为本地文件，不是微信默认提供的文件，也不是用登录密码计算出来。文件名可以自定；数据库密钥须通过当前数据库校验，图片密钥须通过当前账号本地加密图片样本验证。

1. 在目标电脑先手动登录本人 Windows 微信。
2. 启动工具或在 WorkBuddy 说“解析某某群”。程序会发现当前用户常见目录、实际文档目录及可读的微信目录配置提示；不会全盘搜文件。
3. 唯一账号会自动填好，多个账号由用户选择一个；点击“一键自动配置”。先尝试已配置的文件及工具自己 `keys/` 目录中的已有密钥，再为本次操作尝试只读取钥。
4. 只有匹配成功且副本通过解密检查后才列群。成功时密钥保存在本机工作目录 `keys/` 中，并记住路径；数据库和图片密钥可以保存在同一个组合 JSON。

这个按钮会只读访问所选账号唯一对应的微信进程。没有登录客户端、只有离线密文、不受支持的版本或内存布局、归属不唯一、权限不足、超时都可能失败，并显示具体原因，不自动登录或改读别的账号。图片密钥恢复失败时，正文仍可加载，图片缺口继续保留。**不保证每台电脑首次启动都能成功取钥。**

### 后续使用

直接说“解析某某群”，程序会复用已选择的数据和密钥。用户不需要填写技能安装路径、工作目录或长指令。

需要导出时也可说“导出某某群为 JSONL、JSON 和 MD”。解析完成后需在窗口完成人工复核，确认后正式导出三种格式；无需安装 Python 或转换工具。桌面版输入群名按Enter仅定位，再点击左侧解析按钮处理待解析群；相同范围已有结果会复用并保留复核，独立“重新解析”才重置当前目标复核。导出后直接点下方“JSON”“JSONL”“Markdown”查看对应文件，或点“文件所在目录”打开当前群结果目录。没有默认文件关联时会尝试系统记事本。

v11起，程序生成 `解析结果.md` 固定汇报，包含媒体状态、附件类型数量和三种文件链接。Skill原样使用该汇报，并通过WorkBuddy的文件呈现工具同时提供JSONL、JSON、MD入口；无法呈现时保留本地链接并说明。图片缺失、缩略图、本地预览、未加载不会由宿主重新解释，附件数量按程序计算，不从文件名列表估算。

| 文件 | 适合用途 | 内容 |
| --- | --- | --- |
| `messages.jsonl` | 程序逐行处理、大批量消息导入 | 一行一条源消息，保留全部解析字段、原始字段和嵌套转发 |
| `messages.json` | 系统对接、整体读取 | 与JSONL字段、顺序和消息数量一致的JSON数组 |
| `messages.md` | 人工阅读、Markdown工具查看 | 发送人、北京时间、消息ID、原始出处、文字、@、引用、嵌套转发及本地媒体链接 |

三种文件使用UTF-8编码、相同的会话和日期范围，不只导出“业务阅读”筛选后的消息。图片只在确有本地文件时生成链接；缩略图和缺失原件保留提示。MD文件与 `assets/` 一起保存或转移；原始数据库字段在JSONL/JSON中完整保留，MD不逐项重复。已有老导出不会被覆盖，需重新解析生成新文件。

桌面版与 Skill 共用设置、独立副本和导出，个微默认位于当前 Windows 用户的：

```text
%LOCALAPPDATA%\LocalWechatArchive
```

该位置与 Skill 安装目录及版本分离，更新 Skill 可以继续复用设置。更换账号时，在解析窗口点击“数据设置”重新选择。

### 怎样判断完成

| 状态 | 含义 |
| --- | --- |
| `started` / `starting` | 程序已经启动，尚不能据此认定解析完成 |
| `needs_source` | 等待首次选择数据或修正失效的数据设置 |
| `needs_chat` | 指定群不存在或名称重复，需要在窗口选择 |
| `parsing` | 正在解析并核对媒体 |
| `awaiting_review` | 本次解析预览完成，等待人工复核，尚未确认导出 |
| `completed` | 本次人工复核已确认，正式导出完成 |
| `failed` | 本次未完成，应查看具体错误 |

## 4. 不使用 WorkBuddy 也能运行

1. 解压完整桌面便携包，双击 `Start.cmd` 或 `local-chat-desktop.exe`。
2. 首次可登录本人微信后点“一键自动配置”，或切换到手动页选择已有数据和密钥；输入目标群名按Enter定位，再点击主解析按钮，仅处理确认目标。
3. 左侧按ID勾选多个群并解析，逐群查看后点“复核当前群”，保存四项人工检查与备注；保存复核不会导出。全部所选群复核完成后，点击“一键导出所选群”，一次生成各群JSONL、JSON、MD、复核与缺口记录；“打开批次目录”查看批次清单及独立群目录。部分失败可重试，成功群不会重复导出。

桌面版与Skill共用 `%LOCALAPPDATA%\LocalWechatArchive`，企微独立使用 `%LOCALAPPDATA%\LocalWeComArchive`。升级或移动程序不再改变默认配置位置；附近旧版配置通过校验后自动迁移，已有用户配置优先。多账号或远处旧目录可在手动页“导入旧版配置”。详见[配置迁移说明](docs/local-chat/配置迁移说明.md)。

| 查看内容 | 操作 |
| --- | --- |
| 集中查看所有图片 | 点击“图片总览”或同名页签，普通消息、转发及引用中的图片一起显示；可翻页 |
| 放大与核对出处 | 点击卡片图片或“查看大图”；点“定位原消息”回到原消息及上下文 |
| 图片质量状态 | 绿色为原图、黄色为缩略图或本地预览（分别计数）、红色为缺图；未加载媒体另行标记，不当作缺图 |
| 离线图片阅读页 | 导出后点“打开离线图片总览”，或打开 `images.html`；整份导出目录与 `assets/` 应一起保留 |
| 附件 | 选择“附件”筛选或按 `Alt+3`，选中消息后点“打开附件” |
| 转发聊天 | 选择“转发聊天”或按 `Alt+4`，点击消息前的箭头逐层展开 |
| 业务上下文 | 选择“业务阅读”或按 `Alt+7` |
| 缺失图片 | 选择“待补齐图片”，查看具体原因 |

## 5. 是否依赖运行环境

**普通使用者运行交付包，无需安装 Python。运行依赖已经随 EXE 打包。**

| 项目 | 是否需要用户另行准备 |
| --- | --- |
| Python、pip | 不需要 |
| 加密库、图片库、压缩解码组件 | 不需要，已经打包 |
| Docker、数据库服务、原网页工作台 | 不需要 |
| PowerShell | Skill 使用 Windows 自带的 PowerShell 5.1 |
| WorkBuddy | 通过 Skill 使用时需要；独立桌面版不需要 |
| 微信客户端持续运行 | 已有完整副本和匹配密钥时，不要求持续登录微信 |
| PDF、Office 或视频查看器 | 打开对应附件时，需要电脑已有合适的默认查看器 |
| 数据、密钥及读写权限 | 需要自行提供匹配数据和密钥；源文件需可读，工作目录和临时目录需可写 |

开发维护原始 `.py` 源码时，仍需要 Python 及加密、压缩和图片处理依赖；构建便携包还需要打包工具。这些是开发者环境要求，不是普通使用者的安装步骤。

## 6. 换电脑、换宿主是否能使用

### 另一台 Windows 电脑

目标运行平台为 **Windows 10/11 x64**。换电脑时：

1. 携带完整桌面包或 Skill 包。
2. 准备本人有权读取的数据副本和匹配密钥；保留所需 WAL、附件索引及账号媒体目录结构。
3. 新电脑可首次自动发现账号并点击“一键自动配置”；成功依赖已登录客户端及受支持的布局。只有离线副本时手选匹配密钥，成功后自动复用。

数据库密钥按实际数据库内容校验；图片密钥中的旧绝对路径已不再作为拒绝匹配的条件。迁移后不用手动编辑图片密钥中的旧路径。

**当前已完成本机 Windows 10 的隔离迁移验证，另一台物理 Windows 电脑和 Windows 11 尚未实测。** 因此具备便携迁移能力，但不能承诺任意 Windows、任意微信版本或任意组织策略下都能直接运行。32 位 Windows、ARM64、macOS、Linux 不在本轮验证范围内。

当前 EXE 未签名；企业电脑若限制 PowerShell 或未签名程序，需要由 IT 按组织规则放行。

### 其他 AI 宿主

其他宿主需要同时具备：识别或读取 Skill、执行本机 Windows 命令、读写用户指定文件的能力，并获得必要的本地访问授权。

只把 Skill 上传到普通网页聊天窗口，不能据此获得本机程序执行能力。宿主不具备这些能力时，可以使用独立桌面包。其他宿主的自动触发和权限流程需要分别验证。

## 8. 当前缺口及注意事项

### 媒体缺失与正文解码分别统计

v10起，程序回执和 `manifest.json` 提供 `mediaSummary` 分类数据及可直接阅读的 `mediaSummaryText`；WorkBuddy和桌面状态使用同一份统计。旧版混合媒体状态保留作兼容字段，不作为图片数量。

| 分类 | 当前群样本 | 含义 |
| --- | --- | --- |
| 原图 | 6处图片引用 | 已取得可查看原件 |
| 缩略图 | 20处图片引用 | 只能查看缩略图，原图未取得 |
| 缺失图片 | 18处图片引用 | 已核查但没有可显示图片 |
| 未加载图片 | 0处 | 未核查媒体时单独计数，不当成缺失 |
| 附件 | 5处引用，5处可用 | 与图片分开计数 |
| 表情 | 21处引用，均未取得 | 可选内容，不计入图片 |

以上按普通消息、嵌套转发和引用回复中出现的次数统计，与“图片总览”的44处引用一致。同一图片可能在原消息和引用中重复出现，**不等于44张不同图片**；视频封面也不会计作图片消息。表情、附件不会混入“原图/缩略图/缺失图片”数量。仅当未勾选媒体或该项尚未加载时报告“未加载”，不据此判断原件不存在。

附件类型由 `mediaSummary.attachmentTypes` 计算，本样本为2处CSV、1处PDF、1处PPTX、1处XLSX引用，合计5处；各类还保留可用、仅预览、未取得、未加载状态。固定汇报及三格式呈现参数位于回执的 `reporting` 字段；旧版结果需重新解析生成。

正文全部解码成功时，媒体原件仍可能缺失。已删除、未下载或本机不存在的文件不能凭数据库补出。影响业务判断的缺图应保留在事项旁边，不能直接忽略。

### 密钥是必要输入

正常解析使用匹配的已有密钥，只有加密副本不能通用推导出AES密钥。

工具提供用户主动点击的“一键自动配置”和高级恢复入口，需要对应微信正在登录、唯一持有所选数据，并具备读取权限及受支持的内存布局。本轮用户手动登录后，已完成v7无现成密钥的本机成功闭环：新配置新恢复数据库和图片密钥，继续解析并查看指定群；最终便携EXE也在无Python PATH下复验成功。当前实机客户端为微信4.1.15.13，不能据此承诺任意账号、任意版本或另一台物理电脑都成功。

### 私有格式和内容理解有边界

部分WXGF、表情、语音和视频格式尚未完整适配。图片OCR、语音转写和视频内容理解尚未接入。已取得附件的PDF/Office/文本正文现已提取；扫描页、旧格式、图形与超限部分按实际状态保留缺口。

### 原始数据与隐私

- 普通解析只读源数据，查询和导出使用独立副本；程序不会自动发送微信消息或联网下载缺失附件。
- 解析引擎本身不调用外部模型；WorkBuddy读取正文做归纳、上传产物或分享结果时，数据可能进入宿主模型或云端，需按宿主授权和内部资料规则使用。
- 不要把密钥正文粘贴到对话、上传模型或放入公开分发包。聊天、成员资料和附件导出也应作为私有资料保管。
- 本次WorkBuddy分享页已经包含群聊摘要和导出入口，对外转发前需要检查内容并按需脱敏。
- 本地只读可减少客户端交互，不能据此承诺零风控或绕过平台规则。
