# 本地微信聊天解析：操作指南

群聊导出区点击“选择位置…”可指定本机目录，程序记住上次选择，每次新建独立批次子目录，记录与已取得的媒体、附件一起保存。已有文件保留原位置，可在“打开文件 → 另存当前群到指定位置…”保存完整副本。外部目录导出的进度需使用v46或更新版本恢复；恢复时保留所选目录及原工作目录缓存。

当前操作以[复核导出流程](复核导出流程.md)为准：账号加载后列出全部本地群 ID 与名称，可多选批量解析，逐群或批量人工复核后导出。


适用源码版本：桌面 v71 / 群聊 Skill 1.51.5 / 私聊 1.20.3，2026-10-27。运行包需从本仓库源码构建，当前不提供新版 EXE。企业微信客户端请先看 [企微使用说明](企微使用说明.md)：构建后的桌面包双击 `Start-WeCom.cmd`，企微 Skill 包使用 `Start.cmd`，首次配置后复用独立设置。下文默认群聊流程。

搜索框旁可一键清除搜索且保留勾选；在“群资料”中查看完整群名和 ID 并复制。主解析按钮只处理尚无结果或范围已变化的群，其他群复用且保留复核；独立“重新解析”会重置当前目标的复核。搜索回车只定位，不解析。底部提示未解析、未复核或可导出的下一步。小窗口会自动收起辅助说明。

界面采用紧凑排版：常规控件和正文9pt，辅助说明8pt，主标题12pt、群标题11pt；行高按本机字体度量保留空间。完成提示和状态色保留，消息列表获得更多默认阅读空间，全文分隔线仍可拖动。

v69 界面修订恢复群列表与消息列表可见的原生滚动条。内容超出宽度时，拖动列表底部横向滚动条查看群名、完整群 ID 及右侧列；记录较多时使用右侧纵向滚动条。群名和群 ID 列按完整文字展开，也可拖动表头分隔线调整列宽。源码启动后生效，旧 EXE 需重新构建。

普通桌面重开会尝试恢复新版已保存的复核及已完成导出进度：来源、快照及预览摘要均需匹配，原人工确认才能恢复。顶部显示“上次副本”及时间；新消息请点击刷新。旧版未保存的确认不推断为已复核，恢复不会自动导出。成功刷新、成功换号或清除账号缓存会使对应旧进度失效；新来源加载失败保留旧会话与复核；重新解析成功才替换对应群，失败保留旧结果与复核。企微引用原文与本地来源是否可关联分别显示，未知类型保留缺口。

大群后台解析会显示当前群已处理的条数，整理分析与保存进度分阶段提示，不以未知总数显示虚假百分比。后台群先保存可复核材料，打开该群时再建立阅读索引。重启仍保留当前源中尚未完成群的勾选，点击解析会继续缺少或需要更新的群；有效复核不重复处理。批量发布期间源副本发生变化时显示部分完成及原因，已保存群保留，需重新加载来源后再继续。

## 1. 选择运行入口

源码运行和构建命令见仓库 README。统一构建后有共用桌面包、两个群聊 Skill 和两个私聊 Skill；按客户端与会话类型选择，Skill 包必须完整解压或完整导入。下面是构建后的文件名，不能将历史同名包改名冒充新版。

| 使用方式 | 选择的文件 | 启动入口 |
| --- | --- | --- |
| 个微-本地聊天解析 | `WeChat-Archive-Skill-1.51.5-Windows-x64.zip` | 导入后说“打开个微界面让我多选群”；标识wechat-local-archive |
| 企微-本地聊天解析 | `WeCom-Archive-Skill-1.51.5-Windows-x64.zip` | 导入后说“打开企微界面让我多选群”；标识wecom-local-archive |
| 个微私聊 | `local-wechat-private-analysis-1.20.3-windows-x64.zip` | 使用包内 `Start.cmd`，选择联系人；统计和画像另行复核 |
| 企微私聊 | `local-wecom-private-analysis-1.20.3-windows-x64.zip` | 使用包内 `Start.cmd`，选择内部或外部联系人 |
| 直接用桌面窗口 | `desktop.zip` | 完整解压后个微双击 `Start.cmd`，企微双击 `Start-WeCom.cmd`；私聊优先使用对应 Skill 包 |

**不要把外层完整交付ZIP导入为Skill，也不要只复制SKILL.md或EXE。** 1.15.1起，独立Skill的Start.cmd、脚本与直接双击bin内EXE均根据runtime.json校验并绑定客户端；清单缺失、文件混用或客户端冲突会停止。旧1.15.0企微包直接双击EXE可能打开个微，请换新版。 保留独立包内所有文件、许可和校验清单。支持目标为Windows 10/11 x64；不用安装Python、pip、Docker或数据库服务。其他电脑及Windows 11的实际兼容性仍需验证。

## 2. 在WorkBuddy中使用

1. 打开“专家·技能·连接器 → 技能 → 添加技能 → 上传技能”，选择里面的完整Skill ZIP并启用。
2. 新建任务，输入：

   > 解析示例业务群

3. 将“示例业务群”换成实际群名，无需填写程序、数据或密钥路径。
4. 可说“打开企微聊天解析界面，让我选群并人工复核，确认前不要导出”，或个微同类请求；对应Skill使用 `-Mode Desktop`。首次弹窗按下一节配置，已有配置直接复用。指定群解析后返回awaiting_review并等待人工。
5. 勾选区支持当前结果全选/取消、反选、全部群全选及全部取消；搜索保留隐藏勾选。顶部蓝色提示条显示已解析数量与最近完成群，“查看已解析群”可直接筛选定位。群列表前部显示未解析、排队中、解析中、已解析·未复核、已复核；蓝色为可阅读但未复核，绿色为已复核。批量解析时，每群完成即可立即阅读、翻页、筛选和展开转发，不用等待全部群；后台完成不会打断当前阅读。本次队列固定，期间勾选变更用于下次解析/导出。队列完成或停止后，逐群查看正文及缺口，点“复核当前群”完成四项检查和备注，再点“确认复核完成”。可人工点击“全选复核项”一次勾选当前群四项检查，或“清空勾选”；仍需点击确认才保存。列表及顶部显示未复核/已复核，可筛选所选群的复核状态。此时只保存复核，不导出；使用“下一个未复核群”切换。也可点击“批量复核 · N 群”，在一窗查看本次各群摘要与缺口，人工勾选四项、填写共同备注并确认，一次分别保存各群复核。已复核或已导出群跳过，原记录保留；目标失效或文件变化则本次不保存新增复核。全部所选群复核完成后，“一键导出所选群”一次生成对应群的三格式、复核及缺口记录，“打开批次目录”查看全部结果和批次清单。失败可重试，成功群不重复导出。

导出时也可说“导出示例业务群为JSONL、JSON和MD”。每次确认导出都会同时生成三种格式，无需另外安装转换工具。宿主不提供文件呈现工具或呈现失败时，保留本地文件链接并说明，不视为已展示成功。

其他AI宿主需要支持Skill、本机命令执行及文件访问。普通网页聊天窗口仅收到Skill文件，不会自动获得这些本机能力。

## 3. 首次使用或换电脑

### 自动配置

1. 在目标电脑手动登录本人微信。
2. 工具按数据库文件的实际客户端占用关系排列账号，显示运行状态、目录及数据库数量。只有唯一运行账号时才推荐；多个运行账号先选需要的那个。登录后可点击“重新识别运行账号”，不用重新启动。
3. 点击“一键自动配置”。配置窗口在处理期间保持打开，显示进度并禁止重复提交；失败原因在原窗显示，保留输入供重试。只有校验成功才关闭配置窗口。
4. 成功后记住账号配置；已有明确群名的请求只解析该群。直接打开桌面版时，输入目标群名按Enter定位，再点击主解析按钮；完整名称优先匹配，重名时选中正确结果再点左侧解析按钮。搜索只查询群索引，启动及恢复最近群不会解析消息。

切换账号用“账号设置”；只有离线副本用“更多设置 → 手动导入数据副本”。真正换号会清除继承的密钥路径、本人身份及上次群选择；同一账号的上级目录与其 `db_storage`（个微）/`Data`（企微）目录视作同一数据源，保留已有配置。发现另一个运行账号不会自动覆盖当前已保存账号。

空白配置会先要求本人确认账号，启动目录里存在旧工作台也不会直接载入。已有本程序配置仍自动复用；需要工作台副本时，在手动页点击“使用已有工作台配置…”明确导入。

自动配置需要当前客户端、账号、数据和读取权限匹配。未登录、不支持的版本或内存布局、归属不唯一、权限不足等情况可能失败，不能保证每台电脑成功恢复密钥。只有离线密文时不能通用推导密钥。

### 已有离线副本或密钥

切换到“手动选择 / 离线副本”页。

| 选择项 | 文件或目录 | 说明 |
| --- | --- | --- |
| 微信数据目录 | 单个账号的 `xwechat_files\账号目录\db_storage` 或其上级账号目录 | 保留相关WAL、附件索引及账号旁的媒体目录，才能继续定位图片和附件 |
| 数据库密钥 | 与所选副本匹配的密钥JSON | 不是登录密码，也不是settings.local.json |
| 图片密钥 | 匹配的图片密钥JSON | 支持分开提供；数据库密钥JSON已同时包含图片密钥时可留空 |

选好后点“保存并加载”。匹配通过后才能读取记录。不要把密钥正文粘贴到对话或放进转发包。

## 4. 独立桌面版怎么操作

完整解压桌面ZIP，双击 `Start.cmd`，也可双击 `local-chat-desktop.exe`。首次配置与上节相同。

| 需要做什么 | 操作 |
| --- | --- |
| 搜索并解析目标群 | 按ID勾选一个或多个群，点“解析待处理 N 群”；搜索保留勾选，单击或双击只查看。搜索回车只定位唯一结果；无勾选时可用主按钮解析当前目标 |
| 批量选择与复制 | 空格切换当前行，Ctrl+A或“全选当前结果”勾选当前筛选结果；“清空选择”清除所有勾选；复制时每行一个群ID |
| 停止批量解析 | “停止队列”在当前群结束后停止，已完成预览保留；某群失败单独标记并继续其他群 |
| 看图 | 点击“图片总览”，再点图片放大或“定位原消息” |
| 看文件 | 选择附件消息，点“打开附件” |
| 看转发 | 在转发聊天前点箭头，逐层展开 |
| 导出记录 | 逐群保存复核后，“一键导出所选群”；“打开批次目录”看全部，本群文件入口只对应当前群 |
| 查看新增本地记录或缓存 | 在微信完成同步或下载后，点击“更新本地记录” |
| 切换账号 | 点击“账号设置”；清理旧群和旧结果入口，再搜索新账号的目标群 |

搜索不读取各群消息正文；账号准备可能需要复制、解密共享数据库，消息解析和媒体匹配仅针对确认群。找不到目标或重名时不猜选其他群。

图片和转发可在程序内查看；PDF、Office、视频附件需要电脑已有合适查看器。MD/JSON/JSONL没有默认关联时，程序会尝试系统记事本。

解析完成后，附件正文直接显示在详情、HTML、业务阅读与JSONL/JSON/MD；不再只有文件名或打开入口。原文件状态和正文状态分别标记，缺原件或扫描页不当作成功。详见 [附件正文解析说明](附件正文解析说明.md)。

## 5. 怎样理解结果和导出

`completed` 表示本次解析和阅读加载完成；`started`、`starting`、`parsing` 尚不能当作完成。`needs_source` 等待数据配置，`needs_chat` 等待确认群，`failed` 应检查具体错误。

| 输出 | 适合用途 |
| --- | --- |
| `解析结果.md` | 程序生成的固定汇报，媒体数量和附件类型以此及manifest为准 |
| `messages.jsonl` | 每行一条完整源消息，方便程序逐行处理 |
| `messages.json` | 与JSONL相同字段、顺序和嵌套结构的消息数组 |
| `messages.md` | 人工阅读，保留发送人、时间、出处、引用、转发和可用媒体链接 |
| `chat.html` / `images.html` | 离线聊天阅读页 / 图片总览 |
| `业务阅读.txt` | 保留非表情记录上下文，供人工或宿主整理业务 |
| `analysis/` | 业务分析材料：按时间切分的 `part-*.md`（每条带 `#序号`，标注已确认的回复与撤回对象、结构化 @ 姓名和本段发言人身份）、精简 `corpus.jsonl`、`participants.json` 发言人统计、`index.json` 分段与每日条数 |
| `batch-analysis/` | 仅批量导出：群代号、跨群发言人和按时间合并的 `timeline.jsonl`，引用格式 `G序号#ref` |
| `assets/` | 已取得并校验的图片和附件副本 |
| `manifest.json` | 条数、媒体分类、解析状态及产物摘要 |
| `media-recovery.jsonl` | 媒体缺口与本地匹配结果 |

图片的原图、缩略图、本地预览、缺失、未加载五类分开统计；附件、表情、视频和语音另计。**统计单位是普通、转发和引用中的出现次数，同一文件可能重复，不是不同图片张数。** 缺失图片没有可显示文件；缩略图只有预览，原图未取得；未加载表示尚未核查。表情缺失不阻塞业务阅读。

转移记录时，保留整个导出目录及 `assets/`。只转发MD会丢失其引用的图片和附件。JSONL/JSON保留完整原始字段，MD侧重阅读。固定汇报中的绝对本地链接指向原电脑；换电脑后从导出文件夹直接打开messages.md、chat.html或images.html。

WorkBuddy分享页与本地导出目录是不同载体，不能仅凭分享链接认定其他设备能下载本地文件；转发前按实际访问权限确认。聊天导出属于私有数据，是否转发由数据所有者决定。

## 6. 更新时怎样保留配置

桌面版与Skill共用固定用户目录，换解压目录或升级后继续复用。只搜索并解析明确确认的目标群；已有账号配置失效时保留原文件，不自动改读其他账号。

| 客户端 | 桌面与Skill默认配置和导出位置 |
| --- | --- |
| 个微 | `%LOCALAPPDATA%\LocalWechatArchive` |
| 企微 | `%LOCALAPPDATA%\LocalWeComArchive` |

固定目录无配置时自动迁移附近的有效旧配置，复制引用的密钥并保留旧文件；不同账号冲突时等待选择。旧目录不在查找范围时，在“账号设置 → 手动选择 / 离线副本 → 导入旧版配置…”选择旧settings.local.json即可。具体优先级和边界见[配置迁移说明](配置迁移说明.md)。

更换电脑或Windows用户后仍需首次配置本机账号；无需安装Python。旧合并Skill `local-wechat-archive` 应停用，保留两个独立Skill和用户目录。对外只转发原始交付ZIP，不包含使用后的配置、密钥、数据库和导出。

## 启动或初始化窗口异常

双击完整解压包的Start.cmd（桌面企微用Start-WeCom.cmd）直接运行EXE，不需要PowerShell环境初始化。配置对话框不会计时关闭：完成配置或主动关闭前会保留；成功后继续指定群解析。

主窗口点“打开诊断日志”。即使启动失败，系统提示也会显示日志位置：`%LOCALAPPDATA%\LocalChatArchiveDiagnostics\wechat` 或 `wecom` 下的startup-*.jsonl。反馈该日志即可，勿发送密钥文件、数据库、代理地址或附件正文。致命错误提示保留到用户关闭；界面操作失败可在原窗口重试。

WorkBuddy返回needs_source表示窗口等待操作；settings.local.json只在成功后生成。不得把没有设置文件视为程序已经退出。若宿主命令启动受影响，先手动双击Start.cmd完成配置，然后新建任务复用；不必修改系统代理。

## 7. 常见问题

| 情况 | 操作提示 |
| --- | --- |
| 在压缩包中双击后无法启动 | 先完整解压到本人可写目录，再双击Start.cmd；检查系统是否为支持目标的x64版本 |
| 文件被企业策略拦截或隔离 | 按组织规则交由IT处理，不关闭系统防护；当前EXE未签名 |
| 一键自动配置失败 | 查看实际错误；确认本人微信已登录、选对账号。布局不支持时使用匹配的已有副本和密钥，不反复扫描其他账号 |
| 找不到群或同名群 | 核对账号和本地副本，按实际会话ID选择；工具不会联网补拉云端历史 |
| 图片缺失或只有缩略图 | 如有权限，在微信中手动打开原图或下载，再更新本地记录；已删除、未缓存或不支持格式不能保证恢复 |
| 附件已取得但打不开 | 检查本机已有默认查看器；取得文件不代表已理解或验收其中正文 |
| 只看到MD，未看到JSONL/JSON | 核对Skill版本并重新解析，检查exportFiles和固定汇报；三种文件应位于同一导出目录 |
| WorkBuddy界面卡住 | 保留已有结果，正常重启宿主后在新任务重试；避免同时重复发起同一解析请求 |

功能边界详见随包的“个微聊天记录解析工具说明.md”，验证结论和版本信息见“版本与验证说明.md”。

## 图片刚在企微打开后的刷新

## 清除账号缓存与重新配置

多人轮流使用同一台电脑，或演示首次配置时，在“账号设置”底部或“更多设置”选择“清除个微账号缓存…”或“清除企微账号缓存…”，核对客户端和清理目录后确认。请先结束解析、复核或导出操作，并关闭其他解析工具窗口。取消确认不会改动文件。

确认后删除该客户端工具的账号配置、缓存密钥、请求回执、解析副本、预览及复核缓存；未导出的复核结果也会清除。微信原始数据、已导出文件、另一客户端配置和清理目录外的历史备份均保留。清理不会退出微信客户端。

成功后界面清空并重新进入首次配置；重启新版工具也不会自动导入旧配置。人工完成新账号配置后恢复正常使用。部分文件被占用时会明确显示未完成及剩余项目，关闭其他解析工具窗口后可重试；不会把部分失败报告为清理成功。使用Skill发起的旧群解析请求会终止，重新配置后需重新发起。

## v46 解析成功与缺口

明文和密文数据库可以共存；自动取钥只匹配需要解密的库，并包含用户所选的语音库。企微按库保存已验证候选，数据库可使用不同密钥。未登录、账号归属无法确认或候选不匹配时仍不会生成成功结果。

消息时间按行识别秒或毫秒。无法解析时间的记录保留原始字段、来源与缺口说明，即使设置日期范围也不会悄悄丢弃；这些额外记录不能确认在日期范围内，请在复核时核对。异常消息类型、标识和图片预览不会使其余可读取消息全部失败；部分解析和媒体未取得仍明确标注。


本版新增“打开文件 → 补齐清单与处理建议 / 补齐清单表格”，按消息、引用及嵌套转发记录缺口。媒体检索移除512MiB总预算，复用未变化缓存的摘要；首次完整核查可能较久，界面显示已核查文件及读取量。超过单文件100MiB、不可读和变化中的文件单列说明。对图片预览、原图、附件原件与正文分别核查；未关联引用不能解释为没有回复。新解析会生成补齐清单，旧导出仍保留原样；需要补齐时先在客户端打开原图/下载附件，再手动更新该群。


## v47：补原件、扫描文字与密码附件

1. 加载所选账号后，进入“更多设置 → 内容补齐：原件、OCR、密码”。
2. 未缓存原件先在原客户端打开原图/下载附件；可另存到单独目录或使用备份目录，在设置中选为“补充原件目录”。程序按消息原件MD5匹配，重命名不影响，同名但内容不同不会误配。后来新增文件会在下一次解析时重新核查。没有本地副本时仍保留补下载清单，不自动向服务器补拉。
3. 勾选“文档 OCR”，自动处理图片附件、PDF扫描内容及Office内嵌图片；大量聊天图片可按需另启图片 OCR。使用 Windows 已安装的识别语言；缺语言时保留原件并明确失败。OCR不恢复表格结构，小数点/单位须对照原件。
4. 加密附件点“为附件提供密码”，选择原文件并输入已知密码。密码绑定该文件SHA256，只存当前账号会话，退出后清除。也可选择自己保管的密码JSON：`{"schemaVersion":1,"passwords":{"64位文件SHA256":"已知密码"}}`，摘要见补齐清单。程序只记住密码文件路径，不导出密码。
5. 保存设置后，勾选需要补齐的群，点击独立“重新解析”。完成后复核并导出；已发布的旧目录不被覆盖。正常“解析待处理”可能复用旧结果，不能替代此步。

补齐后的文字同时出现在业务阅读、桌面搜索、JSON/Markdown及分析材料。原件、OCR和密码失败仍各自标记；不要把“导出完成”当作所有原件和正文都恢复。


完整性概览：解析后主界面显示当前群的记录、原件/引用、正文/引用及待补齐或核对数量；点击“完整性概览”切换当前群/所选群，查看未解析、复核及正式导出进度，并按图片、附件、正文、OCR、密码、引用来源区分覆盖。大数在概览卡片作万位简写，表格保留精确值。预览不计原件，旧版缺少统计显示待核查；不把导出进度当内容完整率。

## v48：自动补充重要附件正文

在“更多设置 → 内容补齐”启用“文档 OCR”，保存后重新解析指定群。带少量文字的扫描PDF也会识别图片内容；Word、Excel、PPT中的实际引用图片标明文档位置；TIFF逐页读取。原件没有后缀或后缀错误时优先识别文件内容。聊天原图可单独启用。完整性概览和补齐清单继续区分原件取得、正文提取、OCR待复核及失败缺口。

## v49：原件补齐与预览正文

默认取消个微媒体兜底20000文件/2GiB配额；普通文件流式校验摘要并复用未变化结果。双端桌面导出不再因普通原件超过100MiB而拒绝归档，正文20MiB和解码图片容器100MiB上限分别保留。开启聊天图片OCR后，已取得的预览也可识别；sourceQuality=preview、fileStatus=preview_only、extractionStatus=partial、requiresReview明确标注，不能计为原图或全文。

完整性概览中点击“按文件补原件”，打开原件补齐优先清单.csv。按原件MD5合并重复引用、附件优先，保留群/消息定位；无摘要不按同名归并。统计是当前导出范围，多个群的逐群去重数不能直接当跨群唯一文件数。未缓存且无副本的原件仍需客户端取得；下载地址存在不保证可用。


## v50：远程故障日志导出

窗口顶部点击“导出日志”，选择本机ZIP保存位置。解析仍在运行时也可导出，不停止队列、不重跑聊天；随后把ZIP传回用于排查。包内summary.md便于阅读，diagnostics.json记录版本、系统、批次与剩余磁盘空间，events.jsonl记录异常类型、代码位置、处理阶段、计数及诊断编号。目标使用匿名标记，不导出聊天正文、群名、账号、路径、原件、密码或密钥。

默认覆盖最近5份启动/运行日志，每份最多读取末尾2MiB；截断、损坏行与日志落盘失败会在摘要说明。落盘失败时仍可导出当前进程内的最近事件。解析中导出的包只覆盖该时刻，队列结束后可再导出一份。

窗口不能使用时，在桌面包目录运行：`local-chat-desktop.exe --client wecom --export-diagnostics "D:\wecom-diagnostics.zip"`，也可将wecom改为wechat；保存目录须存在且可写。该命令不打开窗口、不读取聊天数据库。旧版本未记录的后台异常无法恢复；请使用v50再次出现问题后导出，不要仅凭通用提示反复取钥或清缓存。

## v51 企微引用解析修复

## v52：异常附件字符不中断整群导出

若 v51 日志显示 offline_chat.py:722 与 utf_8_sig.encode 的 UnicodeEncodeError，更新至 v52，先只重新解析仍失败的群。附件正文中无法编码的字符保留为可见 \uXXXX 标记，状态为部分提取并提示核对原件；不得把该标记当成实际业务内容。原始附件不修改，正常中文、表情及后续记录保留。已有成功群无需重新解析。

## v67：企微运行进程与账号目录排查

任务管理器看到 WXWork.exe，只能证明客户端进程存在。多个 WXWork 子进程不能直接视为多个账号；自动配置仍须核实所选数据库的唯一持有进程。

本版同时检查数据库、现存 WAL 和 SHM 的文件占用；取钥前对消息库、资料识别前对 user.db 使用相同范围。不会根据进程名、PID、内存大小或账号目录名猜选进程。

完整解压后先关闭旧解析窗口，从新包 Start-WeCom.cmd（企微 Skill 使用 Start.cmd）启动，点击“重新识别运行账号”，核对客户端设置中的实际数据目录，再尝试“一键自动配置”。保留原账号缓存、配置和导出；不需要清理账号缓存。工具与企微应运行在同一 Windows 用户下，并核对权限级别及安全软件访问限制，不建议直接关闭安全软件。

若仍未关联，双击 Diagnose-WeCom.cmd。它只检查进程元数据和数据库文件占用，在 Windows TEMP 新建脱敏 JSON 并用记事本打开，不读取进程内存、密钥或聊天正文，不修改账号配置。clientProcessCount 表示客户端进程数，processMetadataDenied 表示元数据不可访问的进程数；accounts 的 processState/ownershipFileCount 表示账号目录占用检查结果。检测到进程但所选库无持有者时，先核对实际数据目录；metadata 不可读时检查用户、权限与访问限制。归属不能确认时仍可使用匹配的已有密钥或已解密副本。

用户提供的 v66 日志来自另一台 Windows 11 电脑：207 条事件中，3 次 SnapshotError 分别位于缺少匹配密钥（1 次）和目录缺必要数据库（2 次）；其余自动配置返回等待配置，没有占用查询详情。截图证明 32 位 WXWork 在运行，不能从现有材料确定是权限、目录或占用查询差异。SHM 检测盲点已用合成回归复现修复；本机只读识别已通过，远程同账号仍需新版复验。

## v68：企微新版数据目录发现

默认检查 `%APPDATA%\Tencent\WXWork\Data`、`%LOCALAPPDATA%\Tencent\WXWork\Data` 及文档目录中的旧版 WXWork，支持直接指定账号目录或其 Data 子目录，并按实际数据库目录去重。只进行有限目录发现，不搜索全盘。

候选列表显示消息库大小、最后写入日期和实际占用状态。在用目录优先；较旧且未确认在用的候选标注“历史候选”。超过90天或同目录标签下更旧、更小只是展示参考，不能证明账号、进程归属或内容失效。唯一已验证在用账号才给出推荐；多个在用账号明确提示人工选择。保留已有配置，需切换时由用户点击选择并保存，不按文件体积、目录名或修改时间自动改写配置。

群聊 Skill 的 `scripts/run.ps1 -Mode Desktop -ScanRoot "自定义扫描根"` 现在会把 roots 经桌面请求和快捷方式传入会话扫描。`-Mode Discover -ScanRoot` 和 Groups 的中文 JSON 输出统一采用 UTF-8；ScanRoot 仅作用本次扫描，不改变已保存 sourceRoot。需多次输入不同目录时重复桌面 EXE 的 `--scan-root`；Skill 的 ScanRoot 接收字符串数组。

恢复上次勾选时保持待确认；点击解析后显示本次实际会话数量，取消不会启动队列。按名称或ID显式请求的单个会话沿用原请求流程。原代码未发现启动时自动续跑整批的行为，本版增加确认防止误启动恢复的勾选范围。

读取到唯一匹配的本人资料后，候选 identityStatus 升级为 self_id_matched，仅用于显示资料匹配；进程归属、密钥校验和人工复核仍分别进行，不以该字段赋予授权。

用户提供的修复指导记录了另一台电脑指定 Roaming 目录后四库匹配和群列表恢复。源码确认原默认扫描漏掉该路径，并以合成的新旧目录并存用例复现修复。指导中“独占打开失败即在用”和按体积自动选择账号的伪代码未采用：现有程序通过 Restart Manager 和进程创建时间核验文件归属，独占打开失败也可能是权限等原因。没有更改加密算法、自动读取真实进程密钥或改写用户账号配置。
