# 私聊内容完整性与复核提示 v66

群聊桌面 v66 / 群聊 Skill 1.51.0 / 私聊 1.20.0。

## 问题与修复

旧统计只显示根消息 parse/decode 缺口。实际合成企微私聊导出中，转发内无正文 PDF 和根消息部分提取 PDF 已进入补齐清单，私聊统计却均未显示。现在沿用 message_nodes 遍历根消息、转发与引用，共用内容分类规则，统计与导出清单保持一致。

contentCoverage 是新增的派生报告字段，schemaVersion=1、unit=reference_occurrence。observedOccurrences 为遍历到的引用出现次数，gapOccurrences 为有任一缺口的节点次数，messagesWithGaps 为涉及的根消息数。issueCounts 各类别可以重叠，不能相加为文件数。documents.withText 只指实际非空文字，不代表完整；noText 只统计明确的 no_text；缺少状态归入 unknownStatus。原 gaps、parseGapCount、decodeGapCount 保持原来的根消息口径。

增加 document_not_checked 与 message_decode_partial 两个补齐类别，不修改 JSONL/CSV 现有结构。已知 no_text、partial、failed 状态在旧记录缺 fileStatus 时仍计入缺口。持久化 ProfileStore 的来源、请求、候选和画像结构不变，无需迁移旧库。

原生内容完整性页与 Markdown、HTML 报告使用同一个展示函数。旧 summary 没有新字段时显示“该版本未统计”，不显示零。界面支持选中一行查看完整说明，最小窗口自动换行。统计报告没有消息或附件正文。搜索结果新增 matchReviewText；原 matchRequiresReview 保留，普通部分附件与实际 OCR 结果分别提示，只有 OCR 尝试元数据不会被当作识别证据。

## 验证与使用

覆盖四个实际导出入口、嵌套同一 PDF 的多次引用、非空文字/空 OCR/未记录状态、旧统计、原生 Tk 界面、编译 CLI 与三种保存报告。检查报告见 execution/parse66-*.json。升级后重新生成私聊统计即可获得新指标；补齐实际正文仍需取得原件并重新解析。已有只读历史导出不会被自动覆盖。
