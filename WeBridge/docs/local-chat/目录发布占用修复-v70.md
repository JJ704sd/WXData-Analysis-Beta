# v70：目录发布占用修复

适用版本：群聊桌面 v70 / Skill 1.51.4。保留 v69 的滚动条和长字段显示修复。

## 日志确认的问题

2026-10-26 提供的 v69 宿主诊断包包含 1247 条事件、19 次异常，程序摘要与已交付 v69 一致。诊断时数据源已加载，156 个群均已解析、失败数为 0；此前仍发生过两次解析收尾失败。其余 17 次异常是正式导出失败事件，包含对相同群的重试，不能当作 17 个不同群。

19 次异常均为目录重命名时的 `PermissionError / WinError 5`：解析阶段位于 `offline_chat.py` 的预览目录发布；正式导出位于 `offline_review.py` 的复核结果发布。日志没有证明缺少企微进程、密钥或磁盘空间，也没有记录阻止重命名的具体程序。

本机 Windows 临时目录实验中，打开目录内文件的读取句柄可以复现同一错误；仅给文件设置只读属性不能复现。该实验确认了可处理的文件占用情形，不能据此断定宿主机占用者或排除目录权限限制。

## 调整后的行为

- 预览和正式导出共用目录发布操作。只有 Windows 返回 `5 / 32 / 33` 时有限等待重试，累计等待最多 3 秒；其他错误立即交回原有流程。
- 持续受阻时明确提示“结果文件已写入，但发布目录仍被占用或禁止重命名”，保留原生错误编号供诊断。失败不标记为已完成。
- 不覆盖已有目标目录；等待期间目标目录被其他操作创建时也会停止。
- 正式导出失败保留已保存的复核与原预览，可直接重试导出。已有成功群继续使用原批次恢复逻辑。

没有调整数据读取范围、附件提取规则或复核条件，没有修改账号、密钥、缓存与已有导出。长期占用或实际权限拒绝仍需在故障电脑处理。

## 更新与恢复

1. 关闭旧解析窗口，完整解压新包，从 `Start-WeCom.cmd` 启动；企微 Skill 包使用 `Start.cmd`。确认窗口显示 v70。
2. 正式导出失败的群可沿用已保存复核，直接重试导出；已成功的群不必重新解析。只有仍显示解析失败的群需要单独重新解析。
3. 持续提示目录发布受阻时，关闭正在读取结果的预览或文件窗口，确认导出位置可写后重试；也可选择新的可写导出位置。无需清企微缓存或重新取钥。
4. 仍失败时导出新版诊断日志，结合失败时间检查该电脑的目录权限及实际占用程序。

## 验证范围

14 项合成检查通过，包括真实 Windows 文件读取句柄造成的临时拒绝、持续拒绝、保留旧复核、失败后免重新解析导出、目标目录冲突、无关磁盘错误，以及原有批次恢复和资源释放检查。

检查使用虚构群和临时文件，不读取真实账号。原故障电脑的实际占用者与更新后导出结果仍需该电脑复验。
