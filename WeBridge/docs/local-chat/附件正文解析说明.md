# 附件正文与状态

只处理本次指定群中已匹配、校验通过的附件，含转发和引用；不会遍历解析其他群，也不下载服务器附件。PDF与Office读取库随EXE提供，不要求安装Python、Word、Excel、PowerPoint或转换服务；打开原文件仍使用电脑已有查看器。

## 输出与兼容

原有消息、asset状态和媒体统计继续保留。在每个file节点增加attachmentContent，v47启用图片OCR时image节点也有此字段，旧导出不被覆盖；需要重新解析生成正文。

- fileStatus：ready、missing、not_loaded、preview_only或integrity_error，专指原文件。
- extractionStatus：extracted（已提取）、partial（部分提取）、no_text（无文字，可能需OCR）、encrypted、unsupported、failed、too_large、timeout、budget_exceeded、original_unavailable或not_requested；v47另有ocr_extracted（待人工核对）、ocr_unavailable、password_rejected、unsupported_encryption及integrity_error。
- text：正文；sections按PDF页、Word段落/表格、Excel工作表与单元格、PPT幻灯片分段。公式不执行，保留缓存值及公式文本；Excel日期可能仍为原始数值。
- source：当前群ID、根消息ID/发送人/时间/serverId、内嵌发送人/时间/part、上下文路径与数据库provenance。
- characters、truncated、notices：实际文字数量、是否截断和限制原因。

JSONL与JSON使用相同内容；MD、业务阅读、离线HTML与桌面详情同步展示正文与状态。manifest及固定汇报增加attachmentTextSummary/attachmentTextSummaryText，按引用出现次数计数。正文取不到时仍保留原件链接和原因。只复制MD也应保留assets目录。

## 格式与边界

| 格式 | 正文能力 |
| --- | --- |
| PDF | 按页提取文本层；可选择使用本机OCR识别无文字页及含位图的混合页，原生文字同时保留，按页保留结果及失败状态 |
| DOCX | 段落、表格、页眉页脚与脚注文字；不还原精确版式 |
| XLSX / XLS | 工作表、单元格地址和原始/缓存值；不计算公式，不执行宏 |
| PPTX | 按实际幻灯片顺序提取段落、表格文字和备注，可识别当前幻灯片实际引用的内嵌图片文字 |
| DOC / PPT | 常见旧二进制格式的结构化文字；标为partial，不声称图形、文本框、修订和精确版式完整 |
| TXT / CSV / MD / JSON / LOG | 本地文字；支持UTF-8及可识别的GB18030编码 |

每文件最多20MB、正文200000字符/1000段；PDF/PPTX最多100页/张。Office展开最多40MB/5000条目。每个唯一内容使用独立进程，超过15秒终止该次提取；OCR工作进程最多60秒，保留已识别页；外层正文进程最多90秒。取消全批180秒预算，单文件失败后继续后续文件。重复文件可复用提取结果，但每处原消息出处单独保存。

v47支持已知密码的PDF与DOCX/XLSX/PPTX，按文件SHA256绑定；密码错误与解密后完整性错误分别报告，不尝试猜测密码。Windows本机OCR支持扫描PDF与PNG/JPEG/BMP/TIFF/WebP原图，结果有requiresReview及ocr元数据。v48 对 DOCX/XLSX/PPTX 当前内容实际引用的内嵌图片批量 OCR；未引用媒体不读取，外链不下载，未识别项标注缺口。图片附件也进入文档 OCR，多页 TIFF/GIF 最多100帧；内嵌多帧图只识别文档显示首帧并说明限制。OCR不恢复原表格结构。partial/no_text与缺少原文件是不同情况，判断业务时保留这些缺口。本文档中的格式能力不等于每种真实业务文件均已实测。

构建固定使用[pypdf 6.16.1](https://pypi.org/project/pypdf/6.16.1/)、[xlrd 2.0.2](https://pypi.org/project/xlrd/2.0.2/)与[olefile 0.47](https://pypi.org/project/olefile/0.47/)，许可随包。旧DOC依据[Microsoft文本片段规范](https://learn.microsoft.com/en-us/openspecs/office_file_formats/ms-doc/01d5d8c4-cf9c-4ef9-80fd-439e763cfe01)，旧PPT依据[TextCharsAtom](https://learn.microsoft.com/en-us/openspecs/office_file_formats/ms-ppt/a3c5c8d5-e530-4167-a242-7743bc99aeac)等结构读取。

Office密码容器使用[msoffcrypto-tool 6.0.0](https://pypi.org/project/msoffcrypto-tool/6.0.0/)，许可随包；OCR使用[Windows.Media.Ocr](https://learn.microsoft.com/en-us/uwp/api/windows.media.ocr.ocrengine)。不依赖云端服务，识别质量受语言和图像清晰度影响。

## v48 自动路由与定位

已校验原件优先按内容签名识别 PDF、常用图片和现代 Office，支持无后缀或后缀错误的附件。图片附件仅在 ocrEnabled 开启时识别，聊天原图由 ocrImages 控制。启用后仍保留原文件 SHA256、declaredFormat 与实际 format。

OCR sections 中新增 ocr.lines（文字行与词框）、width/height/textAngle；coordinateUnit=rendered_pixel 表示识别位图的像素坐标，不是原始PDF点坐标、Excel单元格或可靠表格结构。Office embeddedImages 保留文档部件与上下文；分析材料 attachment.ocrSections 保留同样定位。混合PDF可能同时出现原生与OCR文字，分析时按同页原件核对，不能把两份文字计为两个事件。

## v49：原件补齐与预览正文

默认取消个微媒体兜底20000文件/2GiB配额；普通文件流式校验摘要并复用未变化结果。双端桌面导出不再因普通原件超过100MiB而拒绝归档，正文20MiB和解码图片容器100MiB上限分别保留。开启聊天图片OCR后，已取得的预览也可识别；sourceQuality=preview、fileStatus=preview_only、extractionStatus=partial、requiresReview明确标注，不能计为原图或全文。

完整性概览中点击“按文件补原件”，打开原件补齐优先清单.csv。按原件MD5合并重复引用、附件优先，保留群/消息定位；无摘要不按同名归并。统计是当前导出范围，多个群的逐群去重数不能直接当跨群唯一文件数。未缓存且无副本的原件仍需客户端取得；下载地址存在不保证可用。
