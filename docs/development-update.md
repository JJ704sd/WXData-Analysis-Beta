## 当前改进

四类工具共用同一套最新源码构建，补齐此前只在企微群聊包中交付的滚动与目录发布修复。`chat_release.py` 统一维护版本，桌面标题、能力回执、诊断包和画像 CLI 使用相同来源；`sync_chat_release.py` 同步并检查 Skill 元数据。

群聊打包原来只检查来源包的文件摘要，不能证明 EXE 属于声明的版本。现在先运行无账号副作用的能力查询，核验角色、群聊模式、版本和桌面发布号；旧包、私聊专用程序或元数据不一致时，在写入输出前拒绝。私聊保持桌面与画像 CLI 双重能力校验，并拒绝与源码版本不同的 `--version`。

群聊 `runtime.json` 新增 `release`、`conversationMode` 和 `privateAnalysis` 字段，供统一打包校验使用；现有程序路径、摘要和客户端绑定字段保留。旧清单缺少新增字段时仍沿用原读取逻辑，聊天导出与画像格式不变。

新增 `build_all_chat.ps1` 和 `package_four_chat.py`，从显式指定的同一套桌面及画像程序生成四类包，校验客户端、模式、版本、ZIP CRC 与清单内逐文件摘要，并生成发布矩阵。构建可使用当前 Python 环境或原有 `.runtime/offline-build-deps`，许可证同时从两种依赖位置收集，包含现有 Office 解密依赖。

## 需要继续保留的历史修复

| 已发现问题 | 保留的行为和检查 |
| --- | --- |
| 引用索引 `IndexError` | SQLite 主键列使用稳定别名；旧、新引用标识及 `INTEGER PRIMARY KEY` 场景可解析、复核和导出 |
| 附件 `UnicodeEncodeError` | 孤立代理字符保留为可见转义，标记部分提取；中文、表情和原件保留 |
| 异常后 `WinError 32` | 消息流游标先于连接关闭，异常堆栈保留时也释放文件 |
| 漏发现企微 Roaming 目录 | 保留 Roaming／LocalAppData 和显式扫描根；不凭体积或修改时间确认当前账号 |
| 小窗口滚动、长字段截断 | 原生横纵滚动条可操作，名称和 ID 按文字宽度展开 |
| 目录发布 `WinError 5/32/33` | 仅对相关 Windows 错误等待最多 3 秒；持续失败保留复核，解除占用后直接重试 |
| 引用、转发及附件信息遗漏 | 保留第三方归属、附件全文、位置／名片／小程序和 DOCX 内容控件；删除修订文本不混入正文 |
| 私聊内容缺口统计不一致 | 根消息、转发和引用使用相同内容遍历；提取部分文字不代表完整 |

原规格见 [私聊分析助手 spec](../WeBridge/docs/local-chat/私聊分析助手-spec-v1.0-20261022.md)，具体故障和处理依据见 [v51 引用修复](../WeBridge/docs/local-chat/群聊企微引用修复-v51-20261023.md)、[v54 资源释放](../WeBridge/docs/local-chat/异常中断资源释放-v54.md)、[v68 目录发现](../WeBridge/docs/local-chat/企微Roaming目录发现修复-v68.md) 与 [v70 目录发布](../WeBridge/docs/local-chat/目录发布占用修复-v70.md)。这些文档保留对应版本的历史验证范围。

`wecom-chat-extractor-win.zip` 只用作目录、WAL 和字段布局的参考，没有导入其代码，也没有执行其取钥或报告脚本。该参考包不包含当前助手的媒体补齐和复核版本流程，其按文件时间选账号的方式也没有替换现有账号确认规则。

## 验证边界

当前结果见 [验证记录](validation.json)。合成检查涵盖四类解析／复核／导出、真实 Windows 读取句柄造成的目录占用、旧程序拒绝打包、原生界面和历史解析回归。没有读取真实账号，没有执行远程故障电脑恢复，也没有构建或验证新版 EXE。打包流程的合成验证不能代替真实编译包和宿主导入验收。
