# 企业微信本地聊天解析

群聊导出区点击“选择位置…”可指定本机目录，程序记住上次选择，每次新建独立批次子目录，记录与已取得的媒体、附件一起保存。已有文件保留原位置，可在“打开文件 → 另存当前群到指定位置…”保存完整副本。外部目录导出的进度需使用v47或更新版本恢复；恢复时保留所选目录及原工作目录缓存。

v66 的当前操作以[复核导出流程](复核导出流程.md)为准：账号加载后列出全部本地群 ID 与名称，解析后先人工复核，确认后导出；默认不再直接发布三格式结果。


桌面 v66 / 群聊 Skill 1.51.0，2026-10-25。保留个微和独立的 Windows 企业微信数据源；本版修复按库取钥、秒/毫秒混合时间及异常消息解析，保留逐群导出恢复和清单修复。运行库随 EXE 提供，收包电脑无需安装 Python、pip、Docker 或数据库服务。

企业资料暂不可读时，使用可读company.db中的本人企业列表，按账号ID和企业ID精确补齐；冲突不猜选，企业创建人不作为本人昵称。企业已识别不代表该账号正在运行或聊天库已解密。

账号下拉列表显示“昵称 · 企业简称 · 账号目录 · 运行状态”，选中账号的详情和主界面显示企业全称。现有资料无法读取时显示“企业名称未获取”，可点击“识别运行账号昵称与企业”临时读取已确认归属的运行账号资料；不保存临时密钥，不自动切换或保存账号。企业资料缺失或记录不唯一时保留提示；离线副本如需显示企业信息，应保留同账号的 company.db。

## 一键使用

桌面版：完整解压后双击 **Start-WeCom.cmd**。先在本机登录本人企业微信，在解析器中点击“一键自动配置”；如果发现多个账号，先选择本人要读取的账号。成功后搜索目标群名或ID，按Enter只定位，勾选所需群后点击解析；逐群人工复核完成后再一键导出。以后启动复用已验证配置。

配置过程中窗口会保持打开，失败时显示原因、保留输入，可直接重试。运行账号按所选数据库的持有进程及启动时间验证，不按主进程或子进程数量猜账号。只有全部发现目录完成占用检查且唯一在用时才推荐；多个在用由本人选定，检查不完整显示归属未确认。已保存账号与运行账号不同仍保留原配置，显示差异并提供“选择已确认的运行账号”；此按钮只修改表单，确认配置后才保存。未检测到所选目录占用不代表企微未运行；已有密钥仍可加载离线副本。登录后可点“重新识别运行账号”。配置成功后搜索群名或ID，完整名称优先匹配，按Enter只定位候选；核对会话ID并勾选后点击解析。单击候选、恢复最近群或清空搜索不会解析消息。选择同一账号的上级目录或Data目录不会清空已配密钥、本人身份和最近群聊。

WorkBuddy：导入并启用独立的 `WeCom-Archive-Skill-1.51.0-Windows-x64.zip`，名称“企微-本地聊天解析”（wecom-local-archive），在新任务中说 **“解析企微示例业务群”**，将“示例业务群”换为实际群名。首次弹窗完成上述配置，此后只需这句话。也可说“列出企微群聊”“导出企微示例业务群为JSONL、JSON和MD”。必须带“企微”或“企业微信”，避免同名群与个微混淆。企微Skill已绑定WeCom，用户和宿主均无需填写客户端参数。个微另有“个微-本地聊天解析”（wechat-local-archive），不混用配置。

原有 `Start.cmd` 和不带客户端限定词的短句继续使用个微。

## 首次配置选择什么

通常目录是“文档\WXWork\账号目录”，其 `Data` 下包含 `message.db`、`session.db`、`user.db`，可直接选择账号目录或其 Data 目录。支持使用相同结构的副本；涉及实时写入的副本需连同 `-wal` 保存，媒体保留账号下的 `Cache`。程序只对稳定复制的新副本执行 SQLite 读取。

点击“一键自动配置”后，程序先验证本配置目录已有密钥；没有时，只读访问唯一持有所选数据库的本机 WXWork 进程，验证候选密钥后保存。不会将个微密钥用于企微，不注入、不发送消息、不修改客户端。未登录、进程归属不明确、系统拒绝读取或布局变化时会说明失败。仅有离线密文，不能保证自动取得密钥。

手动密钥采用企微专用 JSON：`wecomKeys` 数组，每项为 `database`（库文件名）与 `key_hex`（16字节主密钥的32位十六进制文本）。这是经过派生和数据库校验的主密钥；不是微信密码、客户端原始密钥材料或个微图片密钥。普通使用不必制作或查看它，也不要把密钥正文粘贴进对话。

本版本企微图片通过文件摘要匹配本机缓存，无需选择个微图片密钥。只有摘要匹配且图片可解码，才作为可用原件；文件名相同或大小相同不能单独证明匹配。旧电脑缓存绝对路径会按当前所选账号的 Cache/Emotion 目录重新定位。

## 可以实现的功能

| 功能 | 当前效果 |
| --- | --- |
| 账号与列群 | 查找当前用户常用文档目录下的企微账号，读取群名称及本地消息数量；多个账号由用户选定 |
| 本地副本解密 | Windows wxSQLite3 AES-128 库，或同结构已解密 SQLite；合并校验通过的已提交 WAL，副本通过 quick_check 后发布 |
| 文字与身份 | 读取文字、内置表情文本、结构化成员提及、链接，保留发送人、北京时间、消息编号、表和原始字段 |
| 图片与附件 | 匹配所选账号 Cache 中的原件和已识别缩略图，原件、缩略图、缺失分别显示；可直接看图、放大、定位原消息和打开受支持附件 |
| 转发聊天 | 解析已映射的企微转发消息，可展开嵌套记录，保留内嵌发送人、时间、层级及根消息出处 |
| 附件正文 | 已取得的PDF、Word、Excel、PPT和文本本地提取正文；原件与正文状态分开，嵌套转发与原消息出处保留；详见 [附件正文说明](附件正文解析说明.md) |
| 三格式导出 | 人工复核确认后同时生成 JSONL、JSON、MD；附阅读 HTML、图片总览、业务阅读、媒体缺口清单和摘要校验 |
| 宿主汇报 | 使用程序固定统计，显示未完整适配的消息及转发数，并提供三种格式入口 |

所有媒体数量是引用出现次数，包含普通和转发中的引用，同一文件可能重复；不是不同图片文件张数。表情包未匹配不强求。

## 已验证与限制

本机 Windows 10 x64、企微 **5.0.12.6018（32位客户端）**，以全新配置且没有现成密钥路径完成自动取钥，4个库副本通过校验，列出21个群，并导出一个真实业务群597条源消息。最终可用媒体数及控件验证结果见“版本与验证说明”。

当前识别文字类型0/2、图片14、文件15/20、视频22/23、转发4、表情29及部分链接/系统类型。未知类型保留原始字段并明确标记。本群有一条邮件卡片尚未完整适配；不能据此声称所有企微消息类型已完整支持。已支持的内嵌引用回复保留回复及原文，包含原文中的受支持图片、附件和转发；能校验同群来源时增加原消息出处。来源标识不足与内嵌原文缺失分别标记，未知引用结构、语音原件和其他特殊卡片仍可能不支持；个微现有引用继续兼容。

其他企微版本、64位企微进程、其他物理 Windows 电脑与 Windows 11尚未完成实际验收。不会从服务器补拉未缓存、已删除或撤回原件；图片不做OCR、语音不转写、视频不识别内容。PDF、Office和视频需电脑已有相应查看器。

## 配置与更新

- 桌面与WorkBuddy企微共用 `%LOCALAPPDATA%\LocalWeComArchive`；个微独立使用 `%LOCALAPPDATA%\LocalWechatArchive`。
- 升级或移动程序不改变上述目录；无现有用户配置时自动迁移附近有效旧配置，复制引用的密钥、保留旧文件。多个账号或远处旧目录在手动页“导入旧版配置”选择，见[配置迁移说明](配置迁移说明.md)。
- 两种配置、密钥和导出相互隔离。首次换电脑在新电脑登录相应账号并配置，不复制旧电脑的绝对路径设置。
- 转移解析结果需保留整个导出目录及 `assets/`。交付 ZIP 不包含本机聊天、媒体、密钥和配置。

常见问题：双击后看到个微说明，检查是否使用 **Start-WeCom.cmd**；列群中无目标群，检查账号与本机实际缓存范围，程序不会切换其他账号猜选；媒体缺失，先在企微手动打开/下载，再刷新副本，不能保证缓存外原件可恢复。

## 已打开图片仍显示缺失

新版支持企微转码、缩放后的本地缓存：按该条消息的缓存路径验证图片后，显示“本地预览（原图未取得）”，与原图、缩略图分别统计。打开原图或下载附件后，点“刷新此群与媒体”，或重新说“解析企微实际群名”；只重读这一群，不用重新选密钥。旧导出不会自动变化，需要重新解析。

若仍无法显示，查看manifest.json里的localMediaSearch及消息asset.reasonCode：可能是缓存已清理、账号不同、缓存不可访问、格式未支持、内容校验失败或补查预算受限。保留原因，不仅凭“已打开过”判定原图在本机。转发只使用该内嵌消息的缓存线索，表情未匹配可跳过。

## 选择日期与查看更多记录

在开始、结束输入框旁点“日历”，可按年月跳转后选一天，也可输入YYYY-MM-DD。点击“应用日期”重新解析当前群：阅读和三格式导出同时限定日期，结束日期包括当天，空白端点不限。点“清空”后再应用可恢复全时段。不会重选账号或取钥。

当前群默认每页300条，可选100/300/500；使用首页、上一页、下一页、末页查看。关键词框按Enter或“筛选”，可查发送人、消息、链接、转发内容和附件正文；清空关键词再筛选恢复原列表。关键词只改变当前群预览，导出仍为所选日期的完整记录。拖动列表与正文之间的横线可调整面积。

## v19 窗口位置说明

- 顶部：刷新当前群、账号设置；“更多设置”中是手动导入与诊断日志。
- 左侧：群名或ID搜索及匹配结果，只解析确认的目标群。
- 右侧上方：消息类型、关键词；点“日期 / 媒体”展开日历与媒体选项。
- 右侧中间：消息列表、完整正文和图片，图片总览在页签中。
- 记录下方：首页、上下页、末页及每页条数。
- 右侧底部：人工复核并导出、JSONL/JSON/MD选择、查看文件和导出目录。

更新后关闭旧窗口并用新入口打开，标题中的 v66 用于识别新版；账号配置继续复用。


本版新增“打开文件 → 补齐清单与处理建议 / 补齐清单表格”，按消息、引用及嵌套转发记录缺口。媒体检索移除512MiB总预算，复用未变化缓存的摘要；首次完整核查可能较久，界面显示已核查文件及读取量。超过单文件100MiB、不可读和变化中的文件单列说明。对图片预览、原图、附件原件与正文分别核查；未关联引用不能解释为没有回复。新解析会生成补齐清单，旧导出仍保留原样；需要补齐时先在客户端打开原图/下载附件，再手动更新该群。

## 异常中断恢复补丁

本次补丁在解析结束或异常中断时先关闭消息查询游标，再关闭数据库连接，避免异常堆栈保留未读完的查询而继续锁住 Windows 快照文件。已完成的复核与导出仍保留，失败会话可单独重试。

## v67：企微运行进程与账号目录排查

任务管理器看到 WXWork.exe，只能证明客户端进程存在。多个 WXWork 子进程不能直接视为多个账号；自动配置仍须核实所选数据库的唯一持有进程。

本版同时检查数据库、现存 WAL 和 SHM 的文件占用；取钥前对消息库、资料识别前对 user.db 使用相同范围。不会根据进程名、PID、内存大小或账号目录名猜选进程。

完整解压后先关闭旧解析窗口，从新包 Start-WeCom.cmd（企微 Skill 使用 Start.cmd）启动，点击“重新识别运行账号”，核对客户端设置中的实际数据目录，再尝试“一键自动配置”。保留原账号缓存、配置和导出；不需要清理账号缓存。工具与企微应运行在同一 Windows 用户下，并核对权限级别及安全软件访问限制，不建议直接关闭安全软件。

若仍未关联，双击 Diagnose-WeCom.cmd。它只检查进程元数据和数据库文件占用，在 Windows TEMP 新建脱敏 JSON 并用记事本打开，不读取进程内存、密钥或聊天正文，不修改账号配置。clientProcessCount 表示客户端进程数，processMetadataDenied 表示元数据不可访问的进程数；accounts 的 processState/ownershipFileCount 表示账号目录占用检查结果。检测到进程但所选库无持有者时，先核对实际数据目录；metadata 不可读时检查用户、权限与访问限制。归属不能确认时仍可使用匹配的已有密钥或已解密副本。

用户提供的 v66 日志来自另一台 Windows 11 电脑：207 条事件中，3 次 SnapshotError 分别位于缺少匹配密钥（1 次）和目录缺必要数据库（2 次）；其余自动配置返回等待配置，没有占用查询详情。截图证明 32 位 WXWork 在运行，不能从现有材料确定是权限、目录或占用查询差异。SHM 检测盲点已用合成回归复现修复；本机只读识别已通过，远程同账号仍需新版复验。

## v68：企微新版数据目录发现

默认检查 `%APPDATA%\Tencent\WXWork\Data`、`%LOCALAPPDATA%\Tencent\WXWork\Data` 及文档目录中的旧版 WXWork，支持直接指定账号目录或其 Data 子目录，并按实际数据库目录去重。只进行有限目录发现，不搜索全盘。

候选列表显示消息库大小、最后写入日期和实际占用状态。在用目录优先；较旧且未确认在用的候选标注“历史候选”。超过90天或同目录标签下更旧、更小只是展示参考，不能证明账号、进程归属或内容失效。唯一已验证在用账号才给出推荐；多个在用账号明确提示人工选择。保留已有配置，需切换时由用户点击选择并保存，不按文件体积、目录名或修改时间自动改写配置。

群聊 Skill 的 `scripts/run.ps1 -Mode Desktop -ScanRoot "自定义扫描根"` 现在会把 roots 经桌面请求和快捷方式传入会话扫描。`-Mode Discover -ScanRoot` 和 Groups 的中文 JSON 输出统一采用 UTF-8；ScanRoot 仅作用本次扫描，不改变已保存 sourceRoot。需多次输入不同目录时重复桌面 EXE 的 `--scan-root`；Skill 的 ScanRoot 接收字符串数组。

恢复上次勾选时保持待确认；点击解析后显示本次实际会话数量，取消不会启动队列。按名称或ID显式请求的单个会话沿用原请求流程。原代码未发现启动时自动续跑整批的行为，本版增加确认防止误启动恢复的勾选范围。

读取到唯一匹配的本人资料后，候选 identityStatus 升级为 self_id_matched，仅用于显示资料匹配；进程归属、密钥校验和人工复核仍分别进行，不以该字段赋予授权。

用户提供的修复指导记录了另一台电脑指定 Roaming 目录后四库匹配和群列表恢复。源码确认原默认扫描漏掉该路径，并以合成的新旧目录并存用例复现修复。指导中“独占打开失败即在用”和按体积自动选择账号的伪代码未采用：现有程序通过 Restart Manager 和进程创建时间核验文件归属，独占打开失败也可能是权限等原因。没有更改加密算法、自动读取真实进程密钥或改写用户账号配置。
