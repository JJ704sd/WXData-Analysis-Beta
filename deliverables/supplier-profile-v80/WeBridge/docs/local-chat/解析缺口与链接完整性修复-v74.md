# v74 解析缺口与链接完整性修复

v74 更新群聊 Skill 至 1.51.8，私聊 Skill 至 1.20.6；日报 1.4.0 保持不变。本次修复针对消息正文进入阅读材料时的缺口边界，保留原始字节、来源、账号范围和人工复核门槛。

## 企微正文缺口

未知或未适配的企微文本块继续在原消息位置显示 `[文本片段未完整解析]`。缺口前后的数字、金额或其他文字不会被拼成新的连续内容；转发、引用和嵌套消息沿用相同规则。原始消息字段仍保留，`parseStatus` 和缺口状态用于提示人工核对。

## 链接边界

从阅读文本提取链接时，只排除实际跨过解析缺口的候选链接。完整的网址分片、普通文本中的链接和用户原本写出的 `[文本片段未完整解析]` 字面内容仍会保留；缺口前后的字符不能被重新组合成一个看似完整的网址。

## 阅读材料提醒

Markdown 和业务阅读 TXT 会在对应消息或嵌套节点旁显示：

`解析提醒：这条消息含有未完整解析的内容，请结合原记录核对。`

HTML 已有逐节点状态提示，不重复追加。媒体或附件单独缺失但正文完整时，不额外显示这条正文解析提醒。

## 使用与验证边界

更新后请重新解析受影响的群聊，检查原消息、阅读材料和链接，再按原流程完成人工复核后导出；旧预览不会自动重写。具体版本、验证范围和未覆盖环境以 [版本与验证说明](版本与验证说明.md) 和交付清单为准。企微缓存中没有对应原件时，本修复不会补拉云端文件，也不会把缺失媒体当作正文已完整解析。

本轮源码定向检查覆盖未知文本块、跨缺口链接、正常分片链接、字面占位符、嵌套节点提醒及四类导出路径。编译包、真实账号、原故障电脑和宿主导入的结果以交付清单中的实际记录为准。
