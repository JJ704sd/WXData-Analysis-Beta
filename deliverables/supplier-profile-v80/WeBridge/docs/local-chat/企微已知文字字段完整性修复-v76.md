# v76 企微已知文字字段完整性修复

v76 更新群聊 Skill 至 1.51.10，私聊 Skill 至 1.20.8；日报 1.4.0 保持不变。本次修复收紧企微已知文字字段和嵌套来源的完整性判断，严格解码规则、原始 bytes、账号范围和人工复核门槛保持不变。

## 已知卡片字段

企微已知 `card` 类型（13、31、38、104）中的非空 `title`、`description` 或 `url` 严格解码失败时，不再继续标记为完整成功。程序保留其他可读字段，记录 `unsupported_text_fields` 并提示部分解析；正常可解码的链接继续保留，无法解码的 URL 不作为链接输出。空的可选字段不新增缺口，也不会凭未知 protobuf 字符串猜测内容。

已知媒体的 `filename` 解码失败时同样标记部分解析，同时保留合法 MD5 和媒体获取流程。101、102 结构仍按既有强校验处理；转发标题失败会保留条目并标记部分解析。

## 转发与引用来源

转发或引用中的非空昵称坏字节会记录为 `sender_name` 的 `metadataIssues` 并提示部分解析；缺失或无效的 ID、时间不会被猜测或补造。正常元数据和引用匹配不变，明确提供的合法值继续保留，嵌套消息原始 bytes 继续保留。

## 使用与验证边界

更新后请重新解析受影响的企微会话，检查卡片字段、媒体、转发和引用来源，再按原流程完成人工复核后导出；旧预览不会自动重写。此修复不承诺恢复坏字段的实际文字或提高真实缓存命中率。具体版本、验证范围和未覆盖环境以 [版本与验证说明](版本与验证说明.md) 和交付清单为准。

本指南只使用包内相对链接。编译包、真实账号、原故障电脑和宿主导入结果以交付清单中的实际记录为准。
