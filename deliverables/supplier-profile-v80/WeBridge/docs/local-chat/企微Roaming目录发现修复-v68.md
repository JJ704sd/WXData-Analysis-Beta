# 企微 Roaming 目录发现修复 v68

## v68：企微新版数据目录发现

默认检查 `%APPDATA%\Tencent\WXWork\Data`、`%LOCALAPPDATA%\Tencent\WXWork\Data` 及文档目录中的旧版 WXWork，支持直接指定账号目录或其 Data 子目录，并按实际数据库目录去重。只进行有限目录发现，不搜索全盘。

候选列表显示消息库大小、最后写入日期和实际占用状态。在用目录优先；较旧且未确认在用的候选标注“历史候选”。超过90天或同目录标签下更旧、更小只是展示参考，不能证明账号、进程归属或内容失效。唯一已验证在用账号才给出推荐；多个在用账号明确提示人工选择。保留已有配置，需切换时由用户点击选择并保存，不按文件体积、目录名或修改时间自动改写配置。

群聊 Skill 的 `scripts/run.ps1 -Mode Desktop -ScanRoot "自定义扫描根"` 现在会把 roots 经桌面请求和快捷方式传入会话扫描。`-Mode Discover -ScanRoot` 和 Groups 的中文 JSON 输出统一采用 UTF-8；ScanRoot 仅作用本次扫描，不改变已保存 sourceRoot。需多次输入不同目录时重复桌面 EXE 的 `--scan-root`；Skill 的 ScanRoot 接收字符串数组。

恢复上次勾选时保持待确认；点击解析后显示本次实际会话数量，取消不会启动队列。按名称或ID显式请求的单个会话沿用原请求流程。原代码未发现启动时自动续跑整批的行为，本版增加确认防止误启动恢复的勾选范围。

读取到唯一匹配的本人资料后，候选 identityStatus 升级为 self_id_matched，仅用于显示资料匹配；进程归属、密钥校验和人工复核仍分别进行，不以该字段赋予授权。

用户提供的修复指导记录了另一台电脑指定 Roaming 目录后四库匹配和群列表恢复。源码确认原默认扫描漏掉该路径，并以合成的新旧目录并存用例复现修复。指导中“独占打开失败即在用”和按体积自动选择账号的伪代码未采用：现有程序通过 Restart Manager 和进程创建时间核验文件归属，独占打开失败也可能是权限等原因。没有更改加密算法、自动读取真实进程密钥或改写用户账号配置。
