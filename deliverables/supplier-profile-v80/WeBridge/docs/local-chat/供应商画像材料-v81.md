# 供应商画像材料

本功能基于已人工复核的本地聊天导出，为供应商画像准备可回查的材料。个微群聊、企微群聊、个微私聊、企微私聊四个入口共用同一分析逻辑。源码基于 v80，新增功能的开发版本为群聊 v81／1.51.15、私聊 1.20.13。

## 桌面操作

1. 使用对应助手，确认账号并解析与供应商有关的会话；核对内容、缺口和日期，完成人工复核和正式导出。
2. 选择“更多设置 → 供应商画像材料…”，选择当前助手内已导出的会话及北京时间范围。确认所选会话确实与同一供应商有关，再输入供应商名称或标识。
3. 群聊会列出各群观察到的发言人及完整 ID；仅选择你确认属于该供应商的成员。同一 ID 在不同群需要分别选择。不选成员时，群聊只作为上下文。私聊只有正式导出记录了对方 ID，且消息发送者与之匹配时，才将其列为对方发言。
4. 选择保存位置。程序在其中新建目录并打开 `report.html`；点击各维度下的原文可跳转，搜索框覆盖本报告的消息和上下文。按实际证据复核后，可复制草稿模板到其他位置填写。

桌面入口一次处理当前账号及当前会话类型的已导出会话。需要合并同一客户端、同一账号的群聊与私聊时，可使用源码或 Windows 包内程序执行下方命令行任务；个微与企微、不同账号不能自动合并。只读取所选会话，不会根据显示名猜测相同供应商或相同联系人。

## 报告内容与判断边界

`report.html` 和 `report.json` 按产品与服务、报价与费用、能力与资源、区域与线路、交付与时效、付款与结算、订单与需求、售后与异常、合作与跟进整理根消息文本的关键词线索。HTML 每个维度显示最近 20 条，完整命中编号在 JSON 中。命中只表示出现过相关用词；否定、询问、假设、失效及矛盾内容均需阅读上下文，不能当作已确认的价格、能力或履约结果。

`evidence.jsonl` 保留消息 ID、完整原消息、发送者、发送时间、来源导出编号、复核编号和原文件行号。用户指定的群成员、已确认的私聊对方、本人或其他成员、身份未知分别标记；群聊其他发言只作上下文。转发、引用和附件保留原作者及出处，不能自动归给当前发送人。时间未知的消息单列，不纳入时段统计与关键词线索。缺失媒体、附件正文或导出日期范围会按已有数据及报告提示核查，无法从聊天中补造。

`画像分析任务.md` 提供给本机或已授权宿主继续整理；`画像草稿模板.md` 应复制到其他位置填写，避免改动带校验清单的报告。`manifest.json` 记录各输出文件的大小和 SHA-256。脚本不会自动调用模型、上传材料或确认画像，也不会改写原始数据、正式导出或已有私聊画像库。

## 同账号跨群聊／私聊

在源码副本外建立 UTF-8 任务 JSON，填写正式导出目录、完整会话 ID 和供应商标识。`groupSpeakers` 按**每个群聊的完整 ID**列出已确认的发言人完整 ID；可省略或留空，此时群消息仅作上下文。发言人 ID 可在单群画像材料的 `report.json`、`evidence.jsonl` 或成员选择窗口中核对。以下值只是格式示例：

```json
{
  "client": "wecom",
  "exportRoots": ["D:/ChatExports/group-reviewed", "D:/ChatExports/direct-reviewed"],
  "chatIds": ["群聊完整ID", "私聊完整ID"],
  "groupSpeakers": {"群聊完整ID": ["已确认的群成员完整ID"]},
  "supplierLabel": "人工指定的供应商名称",
  "start": "2026-10-01",
  "end": "2026-10-31",
  "output": "D:/SupplierReports/new-report"
}
```

在源码副本根目录运行，使用项目现有 Python 环境：

```powershell
.\.venv\Scripts\python.exe WeBridge\scripts\supplier_profile.py --task D:\Tasks\supplier-task.json
```

也可使用解压后的四类 Windows 包执行，不需要安装 Python。根据包内 `runtime.json` 的 `exeRelativePath` 找到桌面 EXE，将下例路径替换为该 EXE；客户端和会话类型须与所选包一致：

```powershell
& .\bin\local-chat-desktop-1.51.15.exe --client wecom --conversation-mode group `
  --supplier-analysis-json D:\Tasks\supplier-task.json --result-json D:\Tasks\supplier-result.json
```

任务中的 `client` 必须与包绑定的客户端一致。已明确选择的群聊与私聊导出可以一起处理，但仍要求属于同一账号。`--result-json` 必须是原始数据、导出和报告目录外尚不存在的文件，返回成功结果或错误；任务格式或路径无法安全确认时不会写入结果文件。

输出目录必须尚不存在，且不能位于原始数据或正式导出目录内。程序检查复核状态、文件摘要、客户端、账号及会话身份；相同消息的重复导出保留多个出处，内容冲突会中止。生成材料后仍需人工核对，不会自动创建已确认画像。

## 验证范围

本次使用合成数据检查四类解析、复核导出、桌面分析入口、跨会话和跨账号边界、成员归属、原文及附件出处、重复导出和校验清单。真实账号、实际业务数据、WorkBuddy 宿主和其他电脑的运行仍需在相应环境验证。
