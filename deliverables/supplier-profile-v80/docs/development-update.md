# 四类聊天助手开发更新

2026-10-28：群聊桌面 v78／Skill 1.51.12，私聊 1.20.10；日报 1.4.0 保持原样。没有改变聊天导出、复核或画像的持久化格式。

## v78 常用时段快捷选择

在既有时段分析窗口加入今天、昨天、近7天、近30天、本周、上周、本月、上月及自定义。快捷范围按北京时间整天填写，本周和本月至今天；修改日期或时刻即转为自定义并保留输入。既有日期范围校验、复核、导出与报告合同不变。说明见 [快捷选择](../WeBridge/docs/local-chat/常用时段快捷选择-v78.md)，本轮定向检查见 [v78 验证记录](presets78-validation.json)。

## v77 指定对象与时段分析

四类入口新增同一账号下的联系人／群聊多选与北京时间范围分析，支持整日、分钟、秒级边界。仅读取所选已复核正式导出，复用身份、复核、摘要与重复消息检查，保留全文、原始字段和出处。生成可搜索 HTML、Markdown、JSON、完整证据、宿主分析任务及摘要清单；时段外回复不参与判断，未知时间单列，日期覆盖空档提示补充材料，不自动调用模型或改写画像。

使用与合同见 [时段分析说明](../WeBridge/docs/local-chat/指定对象与时段分析-v77.md)，实际检查和未验证范围见 [v77 验证记录](period77-validation.json)。

## v76 企微已知文字字段完整性

企微已知 `card` 类型（13、31、38、104）的非空 `title`、`description` 或 `url` 严格解码失败时，记录 `unsupported_text_fields` 并标记部分解析，同时保留其他可读字段；坏 URL 不作为链接，空可选字段不新增缺口。未知 protobuf 字符串不猜字符集，原始 bytes 和严格解码规则不变。

已知媒体 `filename` 解码失败时同样标记部分解析，但保留合法 MD5 和媒体获取流程；101、102 结构继续强校验，转发标题失败保留条目并标记部分解析。转发或引用中的非空昵称坏字节记录 `sender_name` 的 `metadataIssues`，ID/time 不猜测、不补造，正常元数据和引用匹配保持不变。详情见 [v76 修复说明](../WeBridge/docs/local-chat/企微已知文字字段完整性修复-v76.md)。

当前源码、编译包和交付范围以 [v76 验证记录](accuracy76-validation.json) 及交付清单为准；更新后需要重新解析并人工复核，真实账号、原故障电脑和 WorkBuddy 导入仍需实际环境复测。

## v75 附件文本边界与嵌套来源

附件 `TextResult` 不再静默删除 C0 控制字符。需要保留的字符以可见的 `\uXXXX` 形式写入，并标记部分提取、需要复核，避免例如 `金额10\0` 与 `0元` 被错误拼成 `金额100元`。VT、FF 按已知排版规则转换为换行；正常中文、emoji、Tab 和 CR 保持原有内容，不因字符本身新增部分提取状态。

企微转发或无效引用信封缺少 `sender` 或 `time` 时，使用既有未知 ID 和空时间约定，不补造字符串 `0` 或时间 `0`。`metadataIssues`、部分解析提示和原始 bytes 继续保留；明确提供的数值 `0` 保持原值，正常元数据和引用匹配不变。详情见 [v75 修复说明](../WeBridge/docs/local-chat/附件文本边界与嵌套来源修复-v75.md)。

当前源码、编译包和交付范围以 [v75 验证记录](accuracy75-validation.json) 及交付清单为准；真实账号、原故障电脑和 WorkBuddy 导入仍需实际环境复测。

## v74 解析缺口与链接完整性

本轮针对正文进入阅读材料后的信息边界做了小范围修复：未知企微文本块在原位置保留 `[文本片段未完整解析]`，避免缺口前后的数字、金额或其他文字被拼接；转发、引用和嵌套节点沿用相同处理，原始字节、来源和复核门槛不变。

链接提取改为只排除实际跨过解析缺口的候选。正常文本中的网址、跨正常分片的完整网址，以及用户字面写出的 `[文本片段未完整解析]` 不会被误删；缺口前后的字符也不会被重新组合成虚假链接。

Markdown 和业务阅读 TXT 会在对应消息或嵌套节点显示友好解析提醒；HTML 已有逐节点状态提示，不重复追加。媒体或附件单独缺失但正文完整时，不新增正文提醒。详情见 [v74 修复说明](../WeBridge/docs/local-chat/解析缺口与链接完整性修复-v74.md)。

当前 29 项定向源码检查已通过；编译包、宿主导入、真实账号和原故障电脑的结果以 [v74 验证记录](accuracy74-validation.json) 及交付清单为准。

## 当前改进

四类工具共用同一套最新源码构建，补齐此前只在企微群聊包中交付的滚动与目录发布修复。`chat_release.py` 统一维护版本，桌面标题、能力回执、诊断包和画像 CLI 使用相同来源；`sync_chat_release.py` 同步并检查 Skill 元数据。

v73 处理企微已知文本块中的异常非空片段：在原位置保留 `[文本片段未完整解析]`，记录 `unsupported_text_blocks`，不把前后数字拼成新内容；空文本不新增缺口，正常中文、表情、换行、链接和提及顺序继续保留。转发和引用中的同类片段沿用该状态，原始字节保留在正式导出原始字段中。精简语料对已知类型保留可选 `parseStatus`，日报继续通过既有“待补充信息”入口提示。

本账号的 `Emotion` 文件纳入与 `Cache` 相同的 MD5 内容兜底搜索；只有实际内容摘要匹配时才取得本地原件，摘要不匹配、没有原件或搜索未完成时保留缺口。沿用既有分块读取、摘要复用、进度回调及账号和链接边界，本轮未新增扫描限额。

原 v69 诊断包只读回顾见 [宿主日志回顾](host-log-review-v73.json)：1247 条事件中的 19 条异常均为 `PermissionError`／`WinError 5`（2 次解析收尾、17 次导出），继续沿用 v70 的目录发布有限重试；未发现新的独立异常类型，也未在原故障电脑复验。v73 文本缺口和 Emotion 修复来自当前代码的可复现合成夹具，不能归因于这份历史日志。

群聊打包原来只检查来源包的文件摘要，不能证明 EXE 属于声明的版本。现在先运行无账号副作用的能力查询，核验角色、群聊模式、版本和桌面发布号；旧包、私聊专用程序或元数据不一致时，在写入输出前拒绝。私聊保持桌面与画像 CLI 双重能力校验，并拒绝与源码版本不同的 `--version`。

群聊 `runtime.json` 新增 `release`、`conversationMode` 和 `privateAnalysis` 字段，供统一打包校验使用；现有程序路径、摘要和客户端绑定字段保留。旧清单缺少新增字段时仍沿用原读取逻辑，聊天导出与画像格式不变。

新增 `build_all_chat.ps1` 和 `package_four_chat.py`，从显式指定的同一套桌面及画像程序生成四类包，校验客户端、模式、版本、ZIP CRC 与清单内逐文件摘要，并生成发布矩阵。构建可使用当前 Python 环境或原有 `.runtime/offline-build-deps`，许可证同时从两种依赖位置收集，包含现有 Office 解密依赖。

v72 修复附件正文准确性：XLSX 共享字符串和 `inlineStr` 读取复用批注已有的排除规则，不把 `rPh` 注音拼入单元格值；DOCX 保留 `fldSimple` 及同一文本块内跨 run 的复杂 `HYPERLINK` 域的显示文字、链接目标、内部书签或本地路径。字段不执行、不下载，非 `HYPERLINK` 字段不猜目标。原件、出处和既有复核保留，旧预览不会自动重写；需重新解析目标附件会话并人工复核。详见 [正文解析准确性修复-v72](../WeBridge/docs/local-chat/正文解析准确性修复-v72.md)。

## 需要继续保留的历史修复

| 已发现问题 | 保留的行为和检查 |
| --- | --- |
| 引用索引 `IndexError` | SQLite 主键列使用稳定别名；旧、新引用标识及 `INTEGER PRIMARY KEY` 场景可解析、复核和导出 |
| 附件 `UnicodeEncodeError` | 孤立代理字符保留为可见转义，标记部分提取；中文、表情和原件保留 |
| 异常后 `WinError 32` | 消息流游标先于连接关闭，异常堆栈保留时也释放文件 |
| 漏发现企微 Roaming 目录 | 保留 Roaming／LocalAppData 和显式扫描根；不凭体积或修改时间确认当前账号 |
| 小窗口滚动、长字段截断 | 原生横纵滚动条可操作，名称和 ID 按文字宽度展开 |
| 目录发布 `WinError 5/32/33` | 仅对相关 Windows 错误等待最多 3 秒；持续失败保留复核，解除占用后直接重试 |
| 引用、转发及附件信息遗漏 | 保留第三方归属、附件全文、位置／名片／小程序和 DOCX 内容控件；删除修订文本不混入正文 |
| 私聊内容缺口统计不一致 | 根消息、转发和引用使用相同内容遍历；提取部分文字不代表完整 |
