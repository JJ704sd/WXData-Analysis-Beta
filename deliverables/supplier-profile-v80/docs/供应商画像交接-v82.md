# 供应商画像材料交接

本次交接个微群聊、企微群聊、个微私聊和企微私聊四类 Windows 助手：群聊 v82／1.51.16，私聊 1.20.14。四个程序包均完成合成数据的桌面控件与画像输出检查。v82 保留 v81 的供应商画像材料功能，并将范围窗口中误写为“下一步：选择保存位置”的按钮改为“下一步：填写供应商标识”，与实际操作顺序一致。

原 `WXData-Analysis-Beta` 仓库根目录的日报 1.8.0 独立使用。本源码副本附带的历史日报为 1.4.0，不应用它覆盖 1.8.0。

## 使用与交付

从 [v82 发布页](https://github.com/JJ704sd/WXData-Analysis-Beta/releases/tag/chat-assistants-v82)按客户端和会话类型下载相应 ZIP，完整解压后运行 `Start.cmd`。选择获授权账号及供应商相关会话，解析、检查缺口并人工复核导出，再选择“更多设置 → 供应商画像材料…”，指定会话、时间和供应商名称。群聊还需逐群选择经确认属于该供应商的发言人；其他成员的发言只作上下文。私聊对方身份未确认或发送者不匹配时不自动归属。

报告提供产品、报价、能力、区域、交付、结算、订单、售后和跟进等关键词线索，以及原文、导出复核编号和消息行号。线索不等同于已确认的价格、资质或履约结论；请连同否定、问句、历史语境和材料缺口核对原文。合并同一客户端、同一账号的群聊及私聊时，可使用包内任务入口显式指定导出与成员；不同客户端及账号不自动合并。操作与数据边界见 [供应商画像材料说明](../WeBridge/docs/local-chat/供应商画像材料-v81.md)。

## 本次核验与接手事项

2026-11-03 在 Windows 10、Python 3.14.6 环境，以隔离的合成数据库生成会话并模拟人工复核导出，随后分别完整解压四个 ZIP，运行各自 EXE，在程序进程中通过实际 Tk 菜单和控件选择会话、时间、供应商名称及群成员，生成画像报告。四类均核对了报价线索、供应商归属、复核编号与消息行号，以及报告文件摘要；程序运行时移除了 Python 和 Tcl 环境变量。结果见 [桌面检查](supplier82-desktop-validation.json)。

这项桌面检查从已经准备好的合成正式导出开始，以控件调用模拟操作；系统文件夹选择器和浏览器打开使用测试替身，未验证它们的实际交互，也未覆盖人工使用鼠标或桌面端从数据源开始的整套解析、复核操作。另以四个实际 EXE 验证了画像任务、错误客户端拒绝和时间未知消息，见 [程序包检查](supplier82-package-validation.json)。相关源码 33 项检查通过，账号绑定和按钮复测 11 项通过，见 [源码检查](supplier82-source-validation.json)和 [账号绑定检查](supplier82-identity-validation.json)。

尚未使用真实账号、实际业务数据、目标电脑或 WorkBuddy 宿主验证。接手时先在目标环境选择获授权的少量会话，人工确认账号、群成员、日期、系统保存目录和报告打开方式，并逐条回查原文；若附件缺失或提取不完整，应先补齐来源，不根据空白推断业务事实。

源码的 `source-manifest.json` 和 `SHA256SUMS.txt` 以实际字节维护。在源码根目录运行 `python WeBridge/scripts/sync_source_manifest.py` 可校验；新增源码文件应通过 `--update --add <相对路径>` 明确纳入。维护者可用 `WeBridge/scripts/check_supplier_desktop_packages.py` 重新构造隔离合成数据并逐包执行桌面检查；它的 `--work-root` 必须是新的本地目录，结果应与实际包摘要一起保存。
